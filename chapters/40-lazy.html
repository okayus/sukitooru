遅延評価

純粋な式の値は、いつ計算しても変わらない。Haskell の処理系はこれを使い、関数の引数を計算せずに式のままヒープに置き（サンク）、値が初めて要るときに 1 回だけ計算する。この章では、引数をいつ計算するかの規則、サンクの中身と上書き、どこまで計算するか、終わりの無いリスト、代償のスペースリーク、正格な言語の中の遅延を、ghci と GHC 9.6.7 の実測で見る。

  2. 2サンク

第39章で書き換えをやめると、「いつ読むか」が意味から消えた。純粋な式では「いつ計算するか」も結果を変えない。第37章 場面4 の 2 つの順序を、引数をいつ計算するかという言語の規則として見る。

必要呼びは、名前呼びの 2 回め以降の計算を 1 回めの値で済ませる方式である。式が純粋なら何度計算しても同じ値なので、答えは名前呼びと変わらない。Algol 60 のように式の中の変数が途中で書き換わる言語では、この省略はできない。

2サンク — 計算していない式はヒープの物

:sprintghci 9.6.7間接8 バイト × 4

必要呼びの処理系は、計算していない式をどこに置き、計算した値をどう覚えるのか。GHC は式をヒープの上の物（サンク）にし、計算したら結果で上書きする。ghci の :sprint で、その途中の姿が見える。

:sprint は型を [Int] と決めた束縛で見る。型を書かないと xs は多相（Num b => [b]）になって使うたびに作り直され、length xs の後も xs = _ のままだった（GHC 9.6.7 の ghci）。

3どこまで計算するか — 弱頭部正規形

WHNFseq$!非正格

サンクの計算は、誰かが値を要ったときに始まり、要った分で止まる。値を要るのは場合分け・組み込みの演算・入出力の 3 か所で、止まる所はいちばん外の構築子が見えた所（弱頭部正規形）である。

「A History of Haskell」（Hudak ほか、2007 年）は、Haskell は正確には非正格な意味を持つ言語で、遅延評価はその実装の方法の 1 つにすぎないと書く。そのうえで、印象の強い「遅延」の語を慣用に従って使う、と断っている。

4無限のデータ — 要る分だけ作る

[1..]takeWhileHughes 1989短絡

必要呼びでは、要られない所は作られない。だから終わりの無いリストも値として書け、使う側が要る分だけ作る側が動く。作る部品と止める部品を別々に書けることが、遅延評価の大きな利点とされてきた。

Hughes は、合成した 2 つのプログラムの前の方（作る側）を、後の方が入力を読もうとしたときだけ、読む分だけ動かすと説明した。後の方が先に終われば作る側は打ち切られるので、作る側は終わらないプログラムでもよい（1989 年版の 4 節）。

5代償（スペースリーク） — 足さずに積むサンク

foldlfoldl'+RTS -sn ＝ 100 万

遅延評価は、計算を後へ回すぶん、まだ計算していない式をメモリに持つ。それが積み重なると、答えに要る量よりはるかに多いメモリを使う（スペースリーク）。1 から 100 万までの和で、foldl と foldl' を測る。

必ず要る引数を式から見つけ、先に計算してよいと判定する解析を、正格性解析という（Mycroft、1980 年）。GHC では要求解析（demand analysis）と呼ぶ。-O1 で foldl が直ったのはこれによる。判定できない所には、サンクが残る。

6正格な言語の中の遅延 — 引かれて動く列

Iterator#[must_use]function*LazyCell

値呼びが既定の言語にも、遅延の仕組みはある。Rust の Iterator と JavaScript のジェネレータは、使う側が次を引いたときだけ動く列で、作る・変える・止めるを部品に分けられる。

Haskell にも、既定の逆を書く道具がある。seq と $! のほか、データ型の欄に ! を付ける正格なフィールド（Haskell 2010）、束縛やデータの欄を既定で正格にする GHC の言語拡張 Strict・StrictData（GHC 8.0.1 から）。

7まとめ — いつ計算するかを処理系に預ける

  1. 引数をいつ計算するかの規則が評価戦略。値呼びは先に 1 回、名前呼びは使うたび、必要呼びは最初に使うとき 1 回で、止まる限り答えは同じ。違うのは手間と、止まるかどうか（1）。
  2. 計算していない式は、コードの番地と自由変数を持つヒープの物（サンク）になる。計算すると結果への間接に上書きされ、2 回めからは読むだけ。この書き換えは式からは見えない（2）。
  3. 値を要るのは場合分け・組み込みの演算・入出力の 3 か所。計算は外側の構築子か λ が見えた所（WHNF）で止まる。seq・$!・foldl' は値を早めに計算させる（3）。
  4. 要られない所は作られないので、終わりの無いリストを値として書ける。作る・変える・止めるを別の部品にし、止める部品が作る量を決める（4）。
  5. foldl は足し算のサンクの鎖を積み、GHC 9.6.7 の -O0、n ＝ 100 万で最大の常駐量は 49,563,296 バイト（foldl' は 44,328）。-O1・-O2 では GHC が直したが、直るかどうかは式から読めない（5）。
  6. Rust の Iterator と JavaScript のジェネレータは、値呼びの言語の中で引かれたときだけ動く列。いつ計算するかを処理系に預けられるのは、式が純粋だから（6）。
評価戦略関数の引数をいつ、何回計算するかの規則。値呼び・名前呼び・必要呼びなど。
値呼び・名前呼び・必要呼び先に計算して値を渡す（C・Rust・JavaScript）／式のまま渡し、使うたびに計算する（Algol 60）／式のまま渡し、最初に使うときに 1 回だけ計算して覚える（Haskell の処理系）。
サンク（thunk）計算していない式を表す物。計算するコードの番地と自由変数を持つ。GHC 9.6.7 のヒープのサンクは、結果の番地を書く 1 語も持つ。
強制値を要る前に計算させること。seq a b は、値 b を返すまでに a も WHNF まで計算する（どちらが先かは決めていない）。f $! x は値呼びの適用。
弱頭部正規形（WHNF）いちばん外側が構築子か λ になった形。中の欄はサンクのままでよい。サンクの計算はここで止まる。
非正格・遅延評価引数は要るときだけ計算される、という言語の意味（Haskell 2010）と、それを必要呼びで実現する処理系の方法。
無限リスト終わりの無いリスト。[1..]。使う側が要った分だけセルが作られる。
スペースリーク答えに要る量よりはるかに多いメモリを持ち続けること。foldl (+) 0 [1..10⁶] は -O0 で最大の常駐量 49,563,296 バイト。
正格性解析必ず要る引数を式から見つけ、先に計算してよいと判定する解析（Mycroft、1980 年）。GHC では要求解析（-fstrictness）。
