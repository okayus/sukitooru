1ノードと木の形 — struct Node と 21 個の木

node.rs249 行Rc<RefCell<Node>>enum

前の章でトークナイザは test.html を StartTag・Char・EndTag の列にした。パーサはその列から木を作る。まず、木の節（Node）が Rust でどう書かれ、どんな木ができるかを見る。

DOM Standard の Node も同じ 5 つの関係（parentNode・firstChild など）を持つ。ただし仕様には Comment・DocumentType などの種類もあり、saba の 3 種はその一部。木の並びは場面6 のデバッグ出力と同じ。

2Rc・RefCell・Weak — なぜこの形か

RcRefCellWeak参照カウント

ノードは親の first_child、兄の next_sibling、JavaScript から指される。持ち主が 1 つの Rust で共有して書き換える形が Rc<RefCell<Node>> と Weak である。

Rc は単一スレッド用で、数の増減を原子操作にしない。saba は 1 スレッドなのでこれで足りる。複数スレッドで共有するなら Arc と Mutex／RwLock になる。参照カウントは輪を自分では見つけられないので、輪になる向き（上向きと後ろ向き）を Weak にして断つ。

3挿入モード — いまどこにいるか

InsertionMode9 モードmatchcontinue

パーサはトークンを 1 つずつ読むが、同じ <p> でも head の中と body の中では扱いが違う。その「いまどこにいるか」が挿入モードで、saba は enum の 9 つで持ち、match で腕を選ぶ。

HTML Standard の挿入モードは 2026 年 11 月時点で 21。saba に無い 12 は、表（in table など 7 つ）、template、frameset（3 つ）、noscript の分。text モードと戻り先の役割は仕様も同じ。

4要素と文字を入れる — insert_element と insert_char

insert_elementinsert_charfirst_childnext_sibling

InBody に入ると、開始タグは要素のノードに、文字は Text ノードになって木に付く。付ける先はスタックの末尾で、付け方は first_child か兄弟の next_sibling のどちらかである。

insert_char は 2 つめ以降の子を first_child の next_sibling に置くので、<p><a>1</a><a>2</a>3</p> では 2 つめの a が外れて解放される、と読める。文字の直後の開始タグは末尾の Text の子になる。

5スタックで閉じる — pop_until

pop_untilassert!Vec::pop修復なし

終了タグが来たら、開いている要素のスタックを、その種類の要素が出てくるまで pop する。それだけで親子は閉じる。saba が持つ修復はこれと省略タグの補いだけで、仕様の閉じ忘れの補いや入れ違いの直しは無い。

HTML Standard は </body> で body を降ろさず（モードを変えるだけ）、後ろの空白も body に入れ、スタックはパースの終わりにまとめて空にする。saba は </body> で body を降ろし、後ろの文字を捨て、html を積んだまま返す。

6できた木と、使う人 — dom/api.rs と create_frame

page.rsapi.rs深さ優先get_element_by_id

construct_tree が返した Window から document() で根を取れば木全体をたどれる。CSS・JS・レイアウトは、木を深さ優先で歩く api.rs の関数を通して読む。

Chromium は <script> ごとにパーサを止めて実行し、その間もプリロードスキャナが先の CSS や画像を取りに行く。saba が動かすのは、get_js_content が最初に見つけた script の中身 1 つだけで、src 属性で外の JS を取る所も無い。

7まとめ — HTML パーサと DOM

  1. saba の DOM は struct Node の木。中身 kind（Document・Element・Text）と、Rc の first_child・next_sibling、Weak の parent・last_child・previous_sibling。test.html からは 21 個（1）。
  2. Rc は持ち主を数え、RefCell は借用の規則を実行時に確かめ、Weak は数えずに指して輪を断つ。upgrade() が None なら相手は解放済み（2）。
  3. 挿入モードは enum の 9 つ（仕様は 21）。トークンを消費せずに読み直す continue で、省略された html・head・body を補う（3）。
  4. insert_element は current（スタックの末尾）の first_child か、末尾の兄弟の next_sibling に付けて push する。insert_char は空白だけの Text を作らない（4）。
  5. 終了タグは pop_until で、その種類に当たるまで降ろす。Text も一緒に降りる。閉じ忘れの補いや adoption agency の修復は無い（5）。
  6. create_frame が木を作り、api.rs が深さ優先で style・script・id を探す。JavaScript は木が全部できてから動く（6）。
DOM（saba の Node）文書の木。saba では struct Node を Rc<RefCell<Node>> で包んだもの。test.html から 21 個（Document 1・Element 12・Text 8）。
NodeKind と ElementKindノードの種類 3 つ（Document・Element(Element)・Text(String)）と、要素の種類 9 つ（html head style script body p h1 h2 a）。
Rc（参照カウント）持ち主を数える単一スレッド用のポインタ。clone で数が 1 増え、最後の 1 つが消えると値を解放する。Rc::strong_count で読める。
RefCell（実行時の借用検査）borrow()（読む）と borrow_mut()（書く）で中身を貸し、「書く借用は 1 つ、読むと同時は不可」を実行時に確かめる。破れば panic、try_borrow なら Err。
Weak（弱い参照）数えない参照。Rc::downgrade で作り、upgrade() が Option<Rc> を返す。parent・previous_sibling・last_child に使い、参照の輪を断つ。
挿入モードパーサの状態。saba は enum の 9 つ、HTML Standard は 21（2026 年 11 月時点）。original_insertion_mode は Text モードからの戻り先。
開いている要素のスタックVec<Rc<RefCell<Node>>>。末尾が current。saba は Text ノードも積む。
insert_element と insert_char要素・文字を current の子として木に付け、スタックに push する関数。文字は、Text が無いときの '\n' と ' ' を捨てる。
pop_untilその種類に当たるまで pop する。無ければ assert! で panic。InBody で pop_until する終了タグは p・h1・h2・a と body。
Window と document木の根 Document を持つ構造体。construct_tree が Rc<RefCell<Window>> を返し、Page が frame として持つ。
