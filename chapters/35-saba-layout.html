レイアウトと描画

1レイアウトの木を作る — body から下だけ

LayoutView::newbuild_layout_treedisplay: none12 個

前の章の関数 create_layout_object を body から下のノードに当てて、レイアウトの木を作る。display が none のノードは入らず、木は応答のたびに作り直す。

Option<Rc<RefCell<T>>> の木を歩く再帰は、first_child → next_sibling の 2 方向で全ノードを 1 回ずつ訪れる。親への参照だけ Weak なのは、親子で Rc を持ち合うと数が 0 にならず解放されないため（第33章 場面2）。

2定数と文字の升目 — 590×340 と 8×16

constants.rs600×400CHAR_WIDTH 8ratio 1・2・3

文字の大きさは書体から測らず、固定幅のビットマップの字の升目で数える。窓 600×400 からタイトルバー・ツールバー・余白を引いた 590×340 が内容領域で、字は 8×16（行 20）、見出しは 2 倍・3 倍。

wrapping_div・wrapping_rem は、i64::MIN ÷ −1 のときも止まらずに折り返す割り算と余り（/・% はそこで panic する）。ここには正の小さな値しか来ないので、どちらを使っても結果は同じ。

3大きさを決める — compute_size

calculate_node_size下りで幅上りで高さ590×120

大きさは木を 1 回なぞる再帰で決まる。下りながら Block の幅を親の幅にし、葉の Text で字数から大きさを出し、戻りながら Block の高さを子の高さの和にする。body は 590 × 120 になる。

2 回めの compute_size は幅も計算し直すが、Block の幅は親から来るので変わらない。横に並ぶインラインの 2 つめ以降が 1 つめより高い場合や、インラインの列が折り返す場合には、この高さの近似は合わない。test.html にそのような所は無い。

4位置を決める — compute_position

calculate_node_positionタプルの match(88, 80)毎回作り直す

位置も同じ木を 1 回なぞって決める。渡されるのは親の位置と、前の兄弟の種類・位置・大きさ。Block が絡めば前の兄弟の下へ、Inline どうしなら右へ、最初の子は親の位置に置く。再レイアウトは無い。

LayoutPoint の x・y は i64。負の座標も型の上では許すが、この版は 0 以上の小さな値しか作らない。Chromium は 1/64 px 単位の固定小数（LayoutUnit）で位置を持ち、サブピクセルの配置ができる（2026 年時点）。

5表示項目と、窓に描く — DisplayItem と noli の Window

paintRect・Textfill_rect・draw_string＋5・＋31

描く前に、木を「矩形を塗れ」「文字を描け」の列（表示項目）にする。Block は Rect、Text は行ごとの Text、Inline は何も出さない。UI は列を noli の窓へ描き、flush で画面へ出す。

noli の Result は saba の Result と Error の型が違い、? で混ぜられない。update_ui は .is_err() で見て Error::InvalidUI に包み直す（第30章 場面6の型合わせ）。

6操作 — poll するループとヒットテスト

run_appInputModefind_node_by_positionstart_navigation

UI は loop で OS に「マウスは動いたか」「キーは押されたか」を毎周たずねる。ツールバーを押せば URL の編集、内容領域を押せば当たり判定（ヒットテスト）で a を探し、Enter か a で読み込む。

fn(String) -> Result<HttpResponse, Error> の handle_url は main.rs の関数で、UI は型だけを知る（第31章 場面2）。InputMode は値が 2 つの enum で、第29章 場面4の「状態を型で持つ」の例。

7まとめ — レイアウトと描画

  1. レイアウトの木は body から下の、display が none でないノードだけ。first_child と next_sibling の再帰で DOM と同じ形に作り、p.hidden は while で飛ばす。test.html では 12 個（1）。
  2. 文字は書体を見ず、字の升目で数える。内容領域 590×340、字 8×16（行 20）、Text の幅は 8 × 倍率 × バイト数。"My Browser!" は 264×60（2）。
  3. 大きさは 1 回の再帰で決まる。下りで Block の幅（親の幅）、上りで高さ（子の和。横並びのインラインは最初だけ）。body は 590×120（3）。
  4. 位置はタプルの match。Block が絡めば兄の下、Inline どうしは兄の右、最初の子は親の位置。a は (0, 80) と (88, 80)。再レイアウトは無く、応答のたびに作り直す（4）。
  5. 表示項目は Rect（Block の要素の背景）と Text（行ごと）の列で 10 個。UI は x ＋ 5・y ＋ 31 で noli の窓に描き、flush で画面へ（5）。
  6. UI は OS を poll するループ。ツールバーで Editing、内容領域ではヒットテスト（子・兄弟を先に探す）で a を見つけ、start_navigation の 4 段で描き直す（6）。
LayoutObjectレイアウトの木の節。kind（Block・Inline・Text）、DOM ノードへの Rc、子・兄弟・親（Weak）、計算済みスタイル、位置、大きさを持つ。
レイアウトツリー描くノードだけの木。saba では body から下で display が none でないもの。test.html で 12 個。Chromium のレイアウトツリー（第10章）に相当。
CONTENT_AREA内容領域。幅 600 − 5 × 2 ＝ 590、高さ 400 − 24 − 26 − 5 × 2 ＝ 340。レイアウト座標の原点はその左上。
CHAR_WIDTH・CHAR_HEIGHT_WITH_PADDING字の升目 8 × 16 と、行の高さ 20（16 ＋ 4）。XLarge は 2 倍、XXLarge は 3 倍。幅は 8 × 倍率 × バイト数。
compute_size大きさを決める。Block は幅 ＝ 親の幅、高さ ＝ 子の和（横並びは最初だけ）。Inline は子の和。Text はバイト数から、590 を超えたら行を増やす。
compute_position位置を決める。(自分の kind, 前の兄弟の kind) の match で、Block が絡めば兄の下へ、Inline どうしは兄の右へ、最初の子は親の位置。
DisplayItem描画命令の enum。Rect { style, layout_point, layout_size }（Block の要素の背景）と Text { text, style, layout_point }（折り返し行ごと）。test.html で 10 個。
noli の WindowWasabi OS の窓。fill_rect・draw_string・draw_line で窓のシートに描き、flush で画面へ。タイトルバー 24 は noli が描き、座標をその分ずらす。
InputModeUI の状態。Normal（キーを捨てる）と Editing（ツールバーをクリックした後。キーで URL を編み、Enter で読み込む）。
find_node_by_positionヒットテスト。内容領域の座標が入る箱を、子・兄弟を先に探して最も奥のものを返す。親が a なら href へ。
