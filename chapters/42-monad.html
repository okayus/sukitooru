モナド

純粋な関数は、引数から戻り値を決めるほかに何もしない。失敗・状態・入出力のような作用は、戻り値の型（Maybe Int、s -> (a, s)、IO a）に出し、その型の値をつなぐ演算 >>= を型ごとに決めて扱う。型を作る型・return・>>= の組が 3 つの則を満たすとき、それをモナドと呼ぶ。この章では Maybe・State・IO の順に、第37章で言語から外した状態と順序が、型に現れる形で戻ってくることを見る。

  2. 2失敗をつなぐ

1純粋な関数に書けないこと — 作用を型に出す

Int -> Int() => numberMaybe IntIO a

第41章の fmap は、Maybe の値やリストの要素に関数を当てた。この章は、その型を作る型を使って、純粋な関数に書けない失敗・状態・入出力を表す。まず、何が書けないのかを見る。

Haskell は遅延評価で、式がいつ評価されるかは要求で決まる（第40章 場面3）。関数の呼び出しで作用を起こすと順序が定まらないので、純粋さを保ち、作用を型に出す道を選んだ（Hudak ほか「A History of Haskell」、2007 年）。

2失敗をつなぐ — Maybe と >>=

Maybecase>>=and_then?

失敗するかもしれない計算を Maybe で表すと、使う側は毎回 Nothing かどうかを確かめることになる。6 を 3・2・1 で順に割る計算で、その確かめを 1 つの演算 >>= にまとめる。

Haskell の div は負の数を −∞ の向きに丸め（div (−7) 2 は −4）、Rust の / は 0 の向きに切り捨てる（−7 / 2 は −3）。この場面の割り算は正の数なので、両方の言語で同じ値になる。

3モナド — 3 つの部品と 3 つの則

return>>=>=>doApplicative

Maybe の >>= と同じ形の演算は、ほかの型にも作れる。型を作る型 M・return・>>= の組が 3 つの則を満たすとき、その組をモナドと呼ぶ。則を Maybe の具体的な値で確かめる。

計算の作用をモナドで表したのは Moggi（1989・1991 年）、それを Haskell のプログラムの組み立て方にしたのは Wadler（1990・1992 年）。圏論では、自己関手と 2 つの自然変換（単位と乗法）の組をモナドと呼ぶ。

4状態をつなぐ — State

s -> (a, s)newtype0 → 3 → 5 → 6-O2 の Core

状態を書き換えずに扱うには、いまの状態を引数で受け取り、新しい状態を戻り値で返せばよい。第6章 場面4 の sum の列 0 → 3 → 5 → 6 をこの形で書き、受け渡しを State の >>= に任せる。

seq の無い add では、-O2 でも sumS は状態をサンクの鎖で渡す。別のモジュールから n ＝ 10⁶ で呼ぶと最大の常駐量は 38,551,800 バイト（seq 付きは 44,328。+RTS -s）。第40章 場面5の代償は State にも出る。

5入出力 — IO と世界の印

IO amainState# RealWorld-O2 の Core

入出力をする計算の型は IO a である。IO a の値は、実行すると a が得られる入出力の手順で、式を評価しても入出力は起きない。手順を実行するのはランタイムで、入口は main の 1 つだけ。

入出力をモナドで書く方法は Peyton Jones と Wadler の「Imperative functional programming」（1993 年）で、Haskell 1.3（1996 年）から言語の入出力になった。記述と実行を分ける考えは第40章 場面6の続き。

6ほかの形と、ほかの道 — 答え

[a]and_thenthenStateTエフェクト

モナドの形は Maybe・State・IO だけのものではない。答えが複数ある計算や、ほかの言語の Option・Promise にも同じ形がある。最後に、作用を組み合わせる難しさと別の道を見て、章の答えを出す。

モナドを重ねる変換子は Liang・Hudak・Jones（1995 年）が示した。Hudak ほか（2007 年）は、モナドはうまく組み合わさらないと書く。Kiselyov ほかと Kammar ほか（ともに 2013 年）は、ハンドラを変換子に代わる道として示した。

7まとめ — 状態と順序を型に戻す

  1. 純粋な関数は、同じ引数に同じ値を返すほかに何もしない。状態の読み書き・入出力・失敗（作用）は型から見えないので、戻り値の型（Maybe a、s -> (a, s)、IO a）に出す（1）。
  2. Maybe をつなぐたびに書く場合分けを 1 つの演算にしたのが >>=。Nothing が出ると、その先の関数は呼ばれない。Rust の and_then と ? も同じ形（2）。
  3. 型を作る型 M・return・>>= の組が、左単位・右単位・結合の 3 つの則を満たすとき、モナドと呼ぶ。則は a -> M b の関数の合成の則で、コンパイラは確かめない。do は >>= の書き方（3）。
  4. State s a は s -> (a, s) の関数に付けた名前で、>>= が状態を次の計算へ渡す。状態は書き換わる場所ではなく値の列で、GHC 9.6.7 の -O2 では累積引数のループになった（4）。
  5. IO a は入出力の手順という値で、実行するのはランタイム。GHC は IO を世界の印 State# RealWorld の受け渡しで実装する。印は実行時に 0 バイトで、データの依存が順序を固める（5）。
  6. 同じ形はリスト・Rust の Option・JavaScript の Promise にもある（Promise は則 1 が崩れる）。作用を重ねるには変換子、別の道に代数的エフェクト。モナドは、言語から外した状態と順序を型に現れる形で戻す（6）。
作用（副作用）引数から戻り値を決める以外のこと。状態の読み書き、入出力、失敗など。純粋な関数は作用を持たない。
モナド型を作る型 M と、return・>>= の 2 つの演算の組で、3 つの則を満たすもの。Haskell では型クラス Monad。
Maybe値が無い Nothing か、値が 1 つある Just a の直和。失敗するかもしれない計算の戻り値の型。Rust の Option に当たる。
>>=（bind）と doM a と a -> M b から M b を作り、前の計算の結果を次の計算へ渡す演算。do { x <- m; f x } は m >>= \x -> f x と同じ。
return（pure）作用の無い計算を作る演算。Maybe では Just、リストでは [x]。GHC の Monad では、return の既定の定義が pure。
モナド則左単位・右単位・結合の 3 つ。a -> M b の関数の合成 >=> が return を単位とし、括弧の付け方によらないこと。
States -> (a, s) の関数に付けた型の名前。いまの状態を受け取り、結果と次の状態を返す。transformers では StateT s Identity。
IO入出力の手順の型。実行はランタイム。GHC の中身は State# RealWorld -> (# State# RealWorld, a #) で、印は 0 バイト。
Applicative前の結果を見ずに作用を並べる型クラス（pure と <*>）。Monad より弱い形。GHC 7.10 から、Monad の instance には Applicative の instance が要る。
代数的エフェクト計算は操作を呼ぶだけで、その意味を外側のハンドラが決める作用の扱い方。OCaml 5（Effect モジュール）や Koka が持つ。
