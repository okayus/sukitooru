URL と HTTP

第30章のエミュレータに続いて、今度は Rust で書かれた小さなブラウザ saba を 1 行ずつ読む。この章はその入口で、アドレスバーの文字列を Url に分解し、HTTP の要求を組み立てて TCP に書き、返ってきたバイト列を状態行・ヘッダ・本文に切るまでを追う。第10章が Chromium で追った道の最初の区間を、読める大きさの実物でたどる。例は http://host.test:8000/test.html。

    Cargo.toml の 5 つのクレート、#![no_std] と alloc、noli ＝ OS の入口。層への当てはめと行数。

  2. 2main の流れ

    Browser を Rc<RefCell> で作り、WasabiUI に渡し、start(handle_url)。関数ポインタ型が 2 つのクレートをつなぐ。

  3. 3URL を分解する

    Url::parse。http:// を落とし、/ で 2 つに切り、: の手前が host。&str と String。

  4. 4port・path と Result

    port は文字列のまま "8000"、path は先頭の / なし。7 つのテスト。Err を境界で Error に包み直す。

  5. 5要求を組み立てて送る

    lookup_host → TcpStream::connect → GET /test.html HTTP/1.1 を push_str で。改行は LF だけ。

1全体の形 — クレートと層

Cargo.toml#![no_std]allocnoli

第30章の gb-emu-desktop に続いて、Rust の小さなブラウザ saba（ch7 が最終形）を読む。Cargo.toml と lib.rs の頭から、5 つのクレートの分担と、std 無しの事情を見る。

saba が動く Wasabi OS は hikalium/wasabi で公開されている自作の OS で、noli はその上のプログラムが OS の機能を呼ぶためのライブラリである。この章の担当は saba をビルドも実行もしておらず、動きはすべてコードを読んで追った。

2main の流れ — Browser・WasabiUI・handle_url

main.rsRc<RefCell<T>>fn(String) -> Resultentry_point!

URL の文字列は、ui_wasabi から main.rs の handle_url に渡る。main は Browser と WasabiUI を作り start を呼ぶだけ。その引数の型がクレートの間の約束になる。

Rc<RefCell<T>> は「持ち主を数えて共有し、中を書き換えられる包み」で、saba は Browser・Page・DOM の木にこの形を使う。参照カウントと借用の実行時検査の仕組みは、木を作る第33章 場面2 で開く。

3URL を分解する — Url::parse

url.rssplitn(2, "/")find(':')&str

handle_url は最初に URL を分解する。Url は 5 つの String を持ち、parse が http:// を確かめ、/ と : と ? で切って埋める。この場面は host を取るまで。

is_http は部分文字列の検査なので、"ftp://a/?u=http://b" も通る。trim_start_matches は何も落とさず、host は最初の : の手前の "ftp" になる、と読める。テストが確かめるのは正しい入力 5 つと誤りの 2 つ。

4port・path・searchpart と Result

"80"parse::<u16>()#[cfg(test)]Error::UnexpectedInput

残りは port・path・searchpart。port は文字列で持ち、main.rs が u16 にする。7 つのテストが結果を固定し、失敗は Result で返って main.rs が Error に包み直す。

Result<T, E> は成功なら T、失敗なら E で、main.rs は match で両方を書く。第30章 場面6 の gb-emu は失敗を eprintln! で知らせて続けたが、saba は Error に包んで返し、main が 1 を返して終わる。

5要求を組み立てて送る — HttpClient::get

lookup_hostTcpStreampush_str\n

host・port・path から、HttpClient::get が要求を送る。名前解決と TCP の接続は noli を通して OS に頼み、要求は push_str で 1 行ずつ組み立ててバイト列として書く。

第21章 場面1 の要求と形は同じで、違うのは行の終わり（LF の 1 バイト）と、Host に port が無いこと。RFC 9112 §3.2 は Host に authority と同じ host.test:8000 を求める（MUST）。

6応答を読む — HttpResponse と 302

4,096 バイトfrom_utf8split_once302

バイト列を 4,096 バイトずつ最後まで読み、UTF-8 の文字列にして、状態行・ヘッダ・本文に切る。できた HttpResponse の body が HTML の文字列で、次の章はこれを 1 文字ずつ読む。

saba が読むヘッダは Location だけ。Content-Length も Content-Type も Transfer-Encoding も読まない。本文の終わりは接続が閉じたことで知る。chunked の応答なら、長さの行が本文に混ざったまま次の章へ渡る、と読める。

7まとめ — URL と HTTP

  1. saba は 5 つのクレート。#![no_std] で std を外し、alloc で String・Vec を使う。noli が OS の入口、saba_core は依存が無く OS を知らない（1）。
  2. main は Browser を Rc<RefCell> で作り、WasabiUI に渡して start(handle_url) を呼ぶ。引数の型 fn(String) -> Result<HttpResponse, Error> が UI と net の間の約束（2）。
  3. Url::parse は http:// を確かめて落とし、/ で 2 つに切り、: の手前が host。&str は借りた断片、String は持ち主（3）。
  4. port は文字列 "8000"（無ければ "80"）、path は先頭の / が無い "test.html"、searchpart は ? の後ろ。7 つのテストが固定し、Err は Error::UnexpectedInput に包み直す（4）。
  5. HttpClient::get は lookup_host → SocketAddr → TcpStream::connect の後、要求行・Host・Accept・Connection: close・空行を push_str で組み、77 バイトを write する。改行は LF だけ（5）。
  6. 応答は 4,096 バイトずつ 0 まで read し、from_utf8 → \r\n を \n に → split_once で状態行・ヘッダ・本文に切る。302 の転送先は parse() が無く止まる、と読める。body が次の章の入力（6）。
クレート（crate）Rust のコンパイルの単位。saba（実行ファイル）、saba_core・net_wasabi・ui_wasabi（path で指す）、noli（git で取る）。Cargo.toml の [dependencies] と features で結ぶ。
#![no_std] と allocstd を使わない宣言。core は常に使え、ヒープがあれば extern crate alloc で String・Vec・Rc・format! が使える。Wasabi の上で動く saba の全クレートに付く。
nolihikalium/wasabi の for_saba ブランチにある、Wasabi の上のプログラム用のライブラリ。lookup_host・TcpStream・Window・Api::read_key・entry_point!。第9章 場面3 のシステムコールの入口に当たる。
関数ポインタ型fn(String) -> Result<HttpResponse, Error> のように「この形の関数」を値として受け渡す型。外の変数を捕まえないのでクロージャ（第30章 場面5）より単純。ui_wasabi が net_wasabi を知らずに済む。
Rc<RefCell<T>>持ち主を数えて共有する Rc と、借用を実行時に検査して中を書き換えられる RefCell の組。Browser・Page・WasabiUI がこの形。仕組みは第33章 場面2。
Urlurl・host・port・path・searchpart の 5 つの String。例は host "host.test"、port "8000"、path "test.html"（先頭の / なし）、searchpart ""。parse は Result<Self, String>。
&str と String&str は文字列を借りた断片（先頭の位置と長さ）、String はヒープの持ち主。splitn の各片や [..i] は &str で、to_string() で String に写す。
splitn・split_oncesplitn(n, pat) は最大 n 個に切る反復子、split_once(pat) は最初の pat の前後の組を Option で返す。url.rs と http.rs の切り分けはこの 2 つと find・split で書かれている。
Errorsaba_core の enum。Network・UnexpectedInput・InvalidUI・Other（各 String を持つ）。Url::parse の Err(String) は main.rs で UnexpectedInput に包み直す。
HttpResponse と Connection: closeversion・status_code（u32）・reason・headers（Vec<Header>）・body の 5 欄。要求に close を付けたのでサーバーは応答の後に接続を閉じ（RFC 9112 §9.6）、saba は Content-Length を読まず、read が 0 を返すまでを本文にする。

この章で主に読んだのは 6 ファイル（main.rs・url.rs・error.rs・browser.rs と、net と saba_core の http.rs）、テストを除いて 444 行。
