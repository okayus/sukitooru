型推論と多相

Haskell では、関数の引数にも戻り値にも型を書かずに済む。コンパイラが式の使われ方から型の等式を集めて解き、最も一般的な型を決めるからである（Hindley–Milner の型推論）。この章では、その推論の手順と、型を変数のまま残す多相、型ごとに実装を選ぶ型クラスを、GHC 9.6.7 の実際の出力で見る。多相な型は、関数が値に対してできることを縛り、その縛りから関数の性質が導ける。

構成

    分からない型に型変数を置き、関数の適用ごとに等式を 1 本集める。Rust は関数の境目に型を書かせる。

  2. 2単一化

    等式の両辺を同じ形にする代入を求める。形が合わない誤りと、型変数が自分を含む誤り。

  3. 3let 多相と主要型

1型は方程式で決まる

型変数型の等式E0282

第40章の take 3 [1..] は、型を 1 つも書かずに ghci で動いた。それでも GHC は、評価の前にこの式の型を決めている。書かれていない型は、式の使われ方から型の等式を集め、それを解いて決める。

等式を先に全部集めてから解く形は、Pierce『Types and Programming Languages』（2002 年）第22章の説明に合わせた。Milner の 1978 年のアルゴリズム W は、適用を 1 つ見るたびにその場で解く。どちらも同じ型に行き着く。

2単一化

Robinson 1965出現検査GHC-83865GHC-25897

集めた 2 本の等式を解くと、twice の型が決まる。解き方は、等式の両辺が同じ形になるように型変数へ型を代入していく単一化で、解けなければ、それが型の誤りになる。

単一化は Robinson が 1965 年に定理の自動証明（導出原理）に定式化し、Hindley（1969）と Milner（1978）が型の推論に使った。単純型付きラムダ計算の強正規化は、Girard ら『Proofs and Types』（1989 年）第6章に証明がある。

3let 多相と主要型

forallHindley 1969Damas・Milner 1982

twice の t は、使うたびに別の型にしてよい。定義した関数の型は「どの型についても」の形にまとめられ、使う所ごとに新しく具体化されるからだ。まとめるのは let で定義した名前だけで、λ の引数はまとめない。

Hindley–Milner の名は、組合せ論理の項に主要型があることを示した Hindley（1969 年）と、ML の型推論のアルゴリズム W を作った Milner（1978 年）から。W が主要型を返すことは Damas と Milner が 1982 年に証明した。

4型が振る舞いを縛る（パラメトリシティ）

a -> a自由定理Wadler 1989

多相な型は、使う側には自由を与え、書く側には制約を課す。型変数 a の値について何も知らない関数は、その値を調べることも作ることもできない。この制約から、関数の中身を見ずに言える性質が出てくる。

「Theorems for free!」（Wadler 1989）は、どの型からも同様の等式が出ることを示した。元は Reynolds の抽象化定理（1983 年）。再帰と seq のある Haskell では、h が正格などの条件が付く（Johann ら 2004）。

5型クラスと辞書渡し

Num a =>$dNum-ddump-simplE0038

+ は Int にも Double にも使えるが、機械語の足し算は型ごとに違う（第26章 場面3）。型ごとの別の実装を 1 つの名前で呼ぶ多相を Haskell は型クラスで書き、コンパイラは実装の表を隠れた引数で渡す。

型クラスは Wadler と Blott が 1989 年に、型推論を保ったまま + や == を多重定義する方法として提案した。2 つの多相の名は Strachey（1967 年）。Rust の Reference は、影響元に Haskell の型クラスを挙げる。

6型を作る型と Functor

* -> *fmapFunctor の則

Maybe や [] は、それだけでは値の型にならず、型を 1 つ受け取って Maybe Int のような型を作る。この型を作る型を変数にすると、リストと Maybe の map を 1 つの名前にまとめられる。

Functor の名は圏論の関手から来ている。Haskell の Functor は、型を作る型 f と、関数を f の上へ写す fmap の組で、2 つの則はその組が関手であるための条件に当たる。次の章のモナドは、この上に重なる型クラス。

7まとめ — 型推論と多相

  1. 書かれていない型は、分からない所に型変数を置き、関数の適用ごとに型の等式を 1 本集めて決める。Rust は関数の境目の型を書かせ、Haskell と ML は境目も推す（1）。
  2. 等式は単一化で解き、twice は (t -> t) -> t -> t になる。名前の違う型どうし（Bool と Char）と、型変数が自分を含む等式（t1 ＝ t1 → t2）は解けず、型の誤りになる。Ω には型が付かない（2）。
  3. let で定義した名前の型は forall で一般化され、使うたびに具体化される。λ の引数はされない。推論の結果は主要型で、引数を多相にする型などは書く必要がある（3）。
  4. 型変数の値を調べられない関数は、型が振る舞いを縛る。a -> a は止まるなら id だけで、[a] -> [a] の関数は map と順を入れ替えても同じ値を返す。制約があると崩れる（4）。
  5. 型クラスの制約は、実装の表（辞書）を受け取る隠れた引数になり、-O2 は型の決まる呼び出しを特殊化する。Rust の総称は型ごとに写し、dyn は実装の表の番地を値と一緒に持つ（5）。
  6. Maybe・[]・IO は種 * -> * の型を作る型。Functor はそれを変数にした型クラスで、2 つの則はコンパイラが確かめない約束。型は書かなくても決まり、多相な型は関数にできることを縛る（6）。
型推論書いていない型を、式の使われ方から決めること。Haskell と ML は関数の引数と戻り値も推す（Hindley–Milner の型推論）。Rust は関数の中だけ。
型変数まだ決まっていない型、またはどの型でもよい型を表す名前。GHC は a・t・p などの小文字で表示する。
単一化・出現検査2 つの型を同じ形にする代入を求めること（Robinson、1965 年）。型変数を、自分を含む型と等しく置かないかを確かめるのが出現検査。
let 多相（一般化と具体化）let で定義した名前の型に残った型変数を forall でまとめ、使うたびに新しい型変数に取り替えること。λ の引数には行わない。
主要型推論が返す最も一般的な型。正しい型はどれも、その型変数に型を代入した形（Damas・Milner、1982 年）。
パラメトリック多相・パラメトリシティ全部の型で同じ動きをする多相と、型変数の値を調べられないことから出る性質（自由定理）。a -> a は id だけ。
アドホック多相・型クラス型ごとに別の実装を同じ名前で呼ぶ多相（Strachey、1967 年の講義）。Haskell は class と instance で書く（Wadler・Blott、1989 年）。
辞書渡し型クラスの制約を、実装の表（辞書）を受け取る隠れた引数に変える実装。GHC の Core の $dNum。Num の辞書は関数 7 つの組。
種（カインド）型の型。Int は *、Maybe は * -> *、Either は * -> * -> *（GHC 9.6.7 の :k の表示。新しい書き方では * を Type と書く）。
Functor種 * -> * の型 f に fmap :: (a -> b) -> f a -> f b を与える型クラス。則 fmap id ＝ id と合成の則は約束で、コンパイラは確かめない。
