HTML トークナイザ

第31章で応答の本文として受け取った HTML の文字列は、まず 1 文字ずつ読まれてトークンの列になる。それをするのが saba_core/src/renderer/html/token.rs の HtmlTokenizer で、HTML Standard の 84 の状態のうち 17 を写した状態機械が、開始タグ・終了タグ・文字のトークンを返す（4 種めの EOF は定義だけ）。この章は test.html の 810 文字がどの状態でどう切られるかを 1 文字ずつ追いながら、enum に値を持たせる書き方、Iterator トレイト、reconsume の仕組みを読む。コメント・DOCTYPE・文字参照をこの版が扱わないことと、script の中身も Data 状態で切られることも確かめる。

  2. 2状態機械 — Data と TagOpen

    enum State の 18 の場合と loop の 1 周。Data と TagOpen の分岐。<!doctype html> が Char の列になる理由。

  3. 3タグ名と終了タグ

    TagName が latest_token の中の String に 1 文字ずつ足し、> で取り出して返す。as_mut・ref mut・or パターン。

  4. 4属性 — 9 つの状態

    <p class="first"> の 17 文字がたどる道と Attribute { name, value }。引用符の有無、/> と self_closing。

  5. 5script と style の中身

    どちらも Data 状態のまま Char の列になる。ScriptData 系の 5 状態は書かれているが入口が無い。中身に < があると壊れる。

  6. 6EOF と reconsume

    読み直しの旗、終わりの None、返らない Eof。扱わない構文と、仕様の 84 状態との対比。第28章の字句解析との違い。

  7. 7まとめ

    要点と用語。次の章（HTML パーサと DOM）へ。

1文字の列からトークンの列へ — new と next

第31章で手に入った HTML の文字列を、saba は HtmlTokenizer::new で Vec<char> に展開し、パーサが next() を呼ぶたびにトークンを 1 つ返す。

token.rs は 509 行＋テスト 113 行。トークナイザが返すのはトークンだけで、木を作るのは次の章の HtmlParser。パーサは HtmlParser::new(html_tokenizer) で受け取り、欄 t に持つ（parser.rs 37）。

2状態機械 — Data と TagOpen

enum State18 の場合loop と continue仕様は 84

next() は文字を 1 つ取り、いまの状態で分岐し、状態を変えて次の文字へ進むか、トークンを 1 つ返して止まる。これを繰り返す。HTML Standard の状態機械を saba は 18 の State で書く。

doc コメントの /// は rustdoc が拾う説明で、ここでは各状態に対応する HTML Standard の節の URL を置いている。同じ名前で引けば、仕様のその状態の定義と、この版が省いた分岐を並べて読める。

3タグ名と終了タグ — TagName と latest_token

TagNameas_mutref mut と |take

タグ名は latest_token の String に 1 文字ずつ足される。終了タグも同じ TagName で名前を集め、> で Data に戻るときに取り出して返す。Option の中身を扱う書き方が 3 つ出る。

足していく String はヒープに置かれ、push のたびに必要なら伸びる（第31章 場面3の String と &str）。返すときは cloned() の複製が渡り、latest_token は None に戻るので、次のタグは新しい String から始まる。

4属性 — 9 つの状態と Attribute

<p class="first"> の 17 文字は、空白の後 5 つの状態を通って name "class"・value "first" の Attribute になる。属性の状態は 9 つあり、引用符で道が分かれる。

9 つのうち test.html が通るのは、二重引用符の値に至る 5 つだけ。残りの 4 つ（AfterAttributeName・単引用・無引用・SelfClosingStartTag）は、値なし・単引用・無引用・自己終了のために書かれている。

5script と style の中身 — 入口の無い ScriptData

Data のままScriptData 系 5 状態453・465・492 行173 文字

<style> と <script> の中身は、この版ではどちらも Data 状態のまま 1 文字ずつ Char になる。token.rs には script 用の 5 状態が書かれているが、そこへ入る代入が無い。

HTML Standard の script data の系統は 18 状態あり、<!-- の後に <script が書かれていれば、続く </script> を文字として扱う規則まで持つ。saba の 4 状態は、</script> を見つける最小限の部分を写したもの。

6EOF と reconsume — この版が扱わないもの

reconsumepos > lenNone84 対 18

読み直しの旗 reconsume と、入力の終わりの扱いを確かめ、最後に HTML Standard の 84 状態と並べて、この版が扱わない構文を挙げる。字句解析としての形は第28章のものと同じで、違うのは誤りの扱い。

次の章では、このトークンの列を HtmlParser が受け取り、挿入モードと「開いている要素のスタック」で DOM の木にする。Text モードが Char をつなぎ、タグの間の改行と空白を捨てるのもパーサの仕事。

7まとめ — HTML トークナイザ

  1. HtmlTokenizer::new は String を chars().collect() で Vec<char> にし、Iterator の next() がトークンを 1 つずつ返す。HtmlToken は値を持つ enum の 4 種。810 文字 → 543 トークン（計算上）（1）。
  2. next() は loop の 1 周で 1 文字を取り、match self.state で分岐する。continue は次の文字へ、return はトークンを返して止まる。Data は < だけを見て TagOpen へ、TagOpen は英字と / 以外なら < を捨てて Data に戻る（2）。
  3. タグ名は latest_token の String に as_mut と ref mut で 1 文字ずつ足し、> で as_ref().cloned() の複製を返して None に戻す。終了タグは create_tag(false) で同じ道を通る（3）。
  4. 属性は 9 つの状態。start_new_attribute が空の Attribute を push し、add_char(c, is_name) が name か value に足す。引用符の中では " 以外が全部値（4）。
  5. style・script の中身も Data 状態で Char になる。ScriptData 系の 5 状態は書かれているが入口が無く、中身に < があれば壊れる。仕様の script data 状態との差（5）。
  6. reconsume は旗を立てて input[pos − 1] を読み直す。終わりは None で、Eof トークンは返らないと読める。コメント・DOCTYPE・文字参照・RCDATA・RAWTEXT は無く、仕様の 84 状態のうち名前があるのは 17（6）。
トークナイザ文字の列を状態機械でトークンに切る部品。saba では token.rs（509 行）の HtmlTokenizer。木を作るのはパーサ（第33章）。
HtmlTokenトークンの enum。StartTag { tag, self_closing, attributes }・EndTag { tag }・Char(char)・Eof の 4 種。仕様の DOCTYPE・コメント・処理命令は無い。
状態機械と State読んだ文字と「いまの状態」で次の動作が決まる機械。saba の State は 18 の場合（仕様の名前 17 ＋ TemporaryBuffer）。HTML Standard の tokenizer は 84 状態（2026 年 11 月）。
reconsumeいま読んだ文字を次の状態でもう一度読むこと。saba は旗を立て、次の周で input[pos − 1] を返す。test.html では 842 回の消費のうち 32 回。
開始タグ・終了タグ・自己終了<p>・</p>・<img />。名前は小文字に直す。自己終了は self_closing の旗になるが、この版のパーサは読まない。
属性（Attribute）開始タグの name="value" の組。attribute.rs の struct Attribute { name, value }。名前は小文字化、値はそのまま。引用符は二重・単・無しの 3 通り。
Iterator トレイト関連型 Item と fn next(&mut self) -> Option<Item> を持つ Rust の標準トレイト。実装すると呼ぶ側は next() を繰り返すだけでよい。
Vec<char>文字（Unicode のスカラ値、1 つ 4 バイト）の伸びる配列。String（UTF-8 のバイト列）から chars().collect() で作る。添字で 1 文字を引ける。
take（Option を取り出して None に）Option の中身を出して、元を None に戻す操作。saba は as_ref().cloned() と ＝ None で手書きしている。std の Option::take も同じ。
EOF入力の終わり。仕様では各状態が EOF を受けて EOF トークンを出す。saba は next() の冒頭で None を返し、Eof トークンは返らないと読める。

token.rs の全文は sababook のリポジトリで読める。仕様の状態の一覧は HTML Standard 13.2.5 Tokenization。
