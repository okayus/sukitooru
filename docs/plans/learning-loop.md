# 透き通る — 改名・Cloudflare への移行・タグでニュースとクイズと記録をつなぐ

2026-11-22 の持ち主の依頼の設計と段取り。実装は段ごとに新しいセッションで行う（§5）。調査と判断の経緯は、親ディレクトリ（`~/indie-development`）で開いた 2026-11-22 のセッションにある。この計画が済んだら、このファイルは消す（結論は log と各リポジトリの ADR に残す）。

## 1. 依頼とねらい

技術のキャッチアップを、次の 3 つがつながった形にする。

1. インプット: 日刊のニュース（このサイト）。
2. 基礎知識の学習: ニュースの前提を、教材の章と mazuoboeru のクイズで覚える。
3. 振り返りの記録: 読んだことを kokemusu に積む。

つなぐのはタグ。日刊を書くときに、内容のタグと前提のタグを付ける。読者（持ち主）は、前提のタグからクイズへ行き、読んだニュースを内容のタグで kokemusu に記録する。mazuoboeru の日次ダイジェストは、解いたクイズのタグを既に kokemusu の石にしている。ニュースのタグを同じ語彙にすれば、読んだことと解いたことが同じ石に積み上がる。

あわせて、サイトの名前を「透き通る」に変え、配信を GitHub Pages から Cloudflare に移す。いまの名前（YouTube が見えるまで）は、教材の一部の題でしかなくなった。

## 6. 段ごとの要点

### P0 引き継ぎの型

`docs/handoff.md` は 38 KB あり、CLAUDE.md が毎回の最初に読ませている。終わった作業の記録が積み上がったためで、今後の段でさらに増える。「いま」を上限つきの 1 枚にし、履歴と題ごとの計画を別のファイルに分ける。型は okayus-skills の `skills/agent-status-hub`。

- 日刊のクラウドの実行は `docs/daily-news.md` を読む。その実行に「いま」が混ざらないようにする。SessionStart hook がクラウドの実行でも発火するかは確かめていない（§8）。

### P1 改名と移行

並走させてから切り替える。日刊の流れ（毎朝の自動のマージと公開）を止めずに、確かめていない点（§8）を実測するため。章と生成済みの HTML は自サイトの絶対 URL を持たないので、同じ出力が新旧どちらの URL でも動く。

保つもの: 依存ゼロ、`tools/` の道具、`verify.mjs` による検証、日刊の検査の中身。

知っている罠:

- Workers の静的アセットは、既定で `/file.html` を `/file` へ転送する。`assets/engine.js` は `location.pathname` を `.html` で終わる形で照合して章を決める（3 か所）。既定のままだと章の判定が外れる。転送を止める設定にすると、ディレクトリの URL（`/news/`）が `index.html` を返さなくなる。
- いまは main の root が丸ごと公開されている（`docs/` と `tools/` も）。移行のときに、配る範囲を決める。
- 日刊は md だけを足す。ビルドを起こす条件から md を外さない。
- リポジトリの改名で切れるもの: Pages の URL（転送されない）、日刊のルーティンのリポジトリの設定、サイトの URL を直書きした 22 ファイル（ノート、道具の定数 3 か所、文書）。
- ローカルのディレクトリ名（`learning/youtube-ga-mieru-made`）は変えない。Claude Code の記憶と履歴がこのパスに結びついている。
- ビルドの出力や検査を変える変更は、その朝の日刊のプルリクエストがマージされた後に push する。

okayus-skills の `cloudflare-workers-builds-keyless-deploy` の、新しい Worker をつなぐ手順が使える。次の 3 点はこのリポジトリと合わない: md をビルドの条件から外す勧め、pnpm と D1 の migration を前提にしたコマンド、main を ruleset で守る前提（ここは main への直接の push と、ワークフローによる自動のマージ）。移行で確かめたことは、終わってから静的サイトの版として okayus-skills に還元する（還元した。okayus-skills #52、0.5.0、2026-11-24）。

### P2 kokemusu への依頼

なぜ: kokemusu に苔片を作る道は、設定画面で発行する API トークンによる `POST /api/posts` しかない。この道はブラウザの別のサイトからは呼べず（CORS の preflight に答えない設計）、API トークンを公開の静的サイトに置くこともできない。

何を: 外のページのリンクを開くと、積むダイアログが、渡した本文・石・向きの入った状態で開く。投稿は持ち主が押す。一言を足してから積める。

kokemusu の側で決めること（grill-with-docs）:

- 受け取る項目と上限。
- 書きかけの下書きが既にあるときの規則（消さない）。
- 入口の形。渡した内容がサーバーとログに残らない渡し方が望ましい。
- ログインしていないときに、渡した内容を持ち越すか。
- 契約の置き場。送る側（このサイト）が読む文書を kokemusu が公開する。

動かさない前提: 自動では投稿しない。kokemusu は送る側を知らない。契約は受ける側（kokemusu）が持つ。

結果（2026-11-24、kokemusu #87・ADR-0009）: 入口は「リンクで渡す」（`/積む#post=…`。中身は fragment に入れ、サーバーに届かない）。契約は kokemusu の `docs/senders.md`「リンクで渡す」（https://github.com/okayus/kokemusu/blob/main/docs/senders.md#リンクで渡す 、raw は https://raw.githubusercontent.com/okayus/kokemusu/main/docs/senders.md ）で、上限とキーの正本は同じ所の `docs/senders/posts.schema.json`。P4 はこの 2 つを読んで作り、ここには写さない（kokemusu ADR-0008: 写した契約は古くなる）。P4 で導線ができたら、kokemusu の `docs/senders.md` の送り側一覧に実装の場所を足してもらう。本番に入り、持ち主の端末でも確かめた（P2 の出口を満たした）。

### P3 タグ

- 語彙の正本はこのリポジトリに置く。正規の名前、別名（mazuoboeru で割れている同義のタグを受ける）、対応する層を持つ。
- ノートに書くのは内容のタグ。前提のタグは、ノートがリンクした場面の層から自動で出し、層より細かい語だけを書き足す。前提知識の表の概念の名前は 15 件で 73 種あり、重なりは 1 つだった。書き手に自由に書かせると語彙がまとまらない。
- 照合は、mazuoboeru・kokemusu と同じ正規化（NFKC、前後の空白を取る、小文字）で行う。
- 日刊の型（`news/README.md`）、手順（`docs/daily-news.md`）、検査（`tools/news-pr-check.mjs`）を同じコミットで直す。
- 日刊の「動きの場面」の試しは 2026-11-25 に終わり、持ち主が任意のままにすると決めた。日刊の型は、もう変えてよい。

作ったもの（2026-11-25。提案のまま進めた所は、持ち主が変えられる）:

- 語彙: `assets/tags.js`。1 つのタグは id（ページの名前）・正規の名前・別名・対応する層を持つ。正規の名前は、mazuoboeru に同じ概念のタグがあれば、使われた数の多い形にした（kokemusu で同じ石に積もるため。key は大文字と小文字を分けないので、略語は大文字で書く。例: kernel 13 件は「kernel」、セキュリティ 13・security 4 は「セキュリティ」で security は別名）。最初の語彙は、層と既存のノートの話題と、日刊の範囲（`docs/daily-news.md` の 6 つ）から選んだ。
- ノートの印: `tags`（内容のタグ。日刊は 1〜5 個）、`prereqs`（層より細かい前提。4 個まで）、`tag-candidates`（語彙に無い語。3 個まで）。候補は、持ち主が語彙に足すと、そのノートの内容のタグになる（ノートを直さなくてよい）。語彙に入れない語は `ignore` に入れる。層の指定の印は `tags` から `layer` に改めた（`tags` の名前を語彙のタグに使うため）。
- ページ: 表紙の題の下と一覧のカードに、角の丸い札（前提は破線）。タグごとの `news/tag-<id>.html`（内容・前提に持つノート）と、タグの一覧 `news/tags.html`（付いたタグ、候補、語彙の残り）。`news-data.js` に `tags`・`prereqs`。
- 検査: 日刊の検査は、`assets/tags.js` の `checkNote` の strict で、正規の名前だけ・数・候補が語彙に無いことを確かめる。ページを作るときは、別名を正規の名前に読み替えて注意を出し、語彙に無い名前で止まる（正規の名前を変えても、前の名前を別名に残せば既にあるノートは作れる）。`tools/tagcheck.mjs` が語彙を確かめ、`--list` で層ごとの一覧を出す（日刊の書き手が使う）。
- 既存の 18 件には担当がタグを付けた。語彙に無い語が候補として 9 語出た（「リモートコード実行」は 5 件）。持ち主が 9 語とも語彙に足すと決め（2026-11-25）、ノートの内容のタグに移した。語彙は 92 個、ノートに付いているのは 59 個。
- 後に回したこと: ノートの層から前提のタグを自動で出すこと。使うのは P4 の前提のクイズで、層から引くか章から引くかは、mazuoboeru のタグと突き合わせて決める（層「HTTP と DNS」から「HTTP」と「DNS」の両方を出すと広すぎる）。担当が既存のノートの前提に欲しいと挙げた語（プロセス、スレッド、構文解析、浮動小数点数、ASLR、Cookie、文字コード、ポート番号、仮想メモリ、スタックとヒープ、代数的データ型、電子署名、pn 接合）も、そのときに語彙へ足す（プロセスと Cookie は mazuoboeru に process 4 件・cookie 2 件がある）。

### P4 つなぐ

- 記録の導線: ノートのページから P2 の入口を開く。渡すのは、題とリンク、内容のタグと出所の石「透き通る」、向きはインプット。日は読んだ日。公開のサイトなので、導線は持ち主の端末だけに出す。
- 前提のクイズ: ビルドのときに mazuoboeru の公開の一覧を引き、前提のタグに合うクイズへのリンクを置く。引けない日は、リンクなしで作る（ビルドを落とさない）。
- クイズ待ちの一覧: クイズが 1 つも無い前提タグと、それを要るノートを並べる。
