## 台本の書き方を変えたこと（調整役が文書を合わせる）

news/README.md「動きの場面（台本）」と docs/authoring.md §5.6 に足すこと。どれも `assets/anim-script.js` の検査で、誤りは行番号つきで止まる（11 は部品の console.error）。

1. **綴りの違う操作は誤り。** 段階の中の「英小文字の語: id の並び」「語: a -> b …」「語: a = …」「語: -」の形の行は操作として読み、`show` などの 9 つ以外なら「読めない操作の行」にする。前は本文に混ざってページに出た（`shwo: m1` など）。
2. **`send:` は、同じ 2 つの間は 1 段階に 1 つ**（行きと帰りは段階を分ける）。前は検査を通り、boxes では onStep が例外になり（1 つ目の send の線が見つからず `l.it` を読む。コードを読んで確かめた）、mem・tree では 2 つの札が同じ所に重なった。
3. **`send:` が通る line（boxes）と edge（tree）は、その段階で見えていること。** 前は隠れた線の上を粒が流れた。
4. **boxes の line は、途中の升目にある箱の上を通れない。** 線は箱の真ん中どうしを結ぶ直線なので、`1,1` と `3,1` を結ぶと `2,1` の箱を横切る（列・行の差の最大公約数で、通る升目を出す）。
5. **title と note は図の上の 1 行に並ぶ。** 「title の幅 × 1.3 ＋ note の幅」を 78 までにする（title は 12.5px の太字、note は 10px）。それでも並ばない字（M・W が多いなど）のときは、部品が note を 2 行目（y 46）に下げる。
6. **本文と caption に `[[…]]` と `{e|…}` は使えない。** 色の語は parts.html では効くが、ニュースのページ（build-news.mjs の `inline`）では記号のまま出る。強調は `**太字**`。
7. **日刊のノートは `down:` の行き先に段階の番号を書けない**（`19-tcp.html#s2.1` は誤り。README の決まりを検査に入れた）。詳しいノートは書ける。
8. **箇条書きの直後（空行なし）の ```` ```anim ```` は誤り。** build-news.mjs は箇条書きを空行まで読むので、台本が箇条書きの文になり、build-news が「台本の数が合わない」で止まっていた（いまは行番号つきで止まる）。

## 直さずに報告すること

1. **verify.mjs と shot.mjs は、上限いっぱいの台本の `parts.html?part=…&src=…` を撮れない。** 写真の名前に問い合わせを全部入れる（`pageStem`）ので、URL 13〜16 KB の台本では名前が長すぎて書けない（ENAMETOOLONG）。また配信の Node の http は見出しの上限 16 KB で、timeline の上限の台本（URL 15.9 KB）は 431 で開けなかった。scratchpad の写し（名前を 40 字で切り、`--max-http-header-size=131072`）で測った。直すなら `pageStem` を切るかハッシュにし、`http.createServer` に `maxHeaderSize` を渡す（どちらも受け持ちの外）。
2. **build-news.mjs の `inline()` は `[文字](javascript:…)` をそのままリンクにする**（台本の本文もこの `inline` を通る）。日刊は news-pr-check.mjs が https・http 以外のリンクを拒むので届かない（模擬で確かめた）。詳しいノート（持ち主が書く）だけの話。直すなら `inline` で、http(s)・相対・`#` 以外の行き先を文字のままにする（ノートの Markdown 全体の扱いなので受け持ちの外）。
3. **ワークフローの verify.mjs は `--overlap` と `--drill` を付けない**（`--sizes all` だけ）。日刊の台本の文字の重なりと印の板は、マージの前に誰も見ない。`--overlap` は注意だけで失敗にしない作りなので、付けても止まらない。11 の edge の誤りは console.error なので、今のままで落ちる。
4. **札の幅の上限（`units`）は英数字を一律 0.56 と数える。** 実際の幅は M・W が 0.94〜0.97em、記号が 0.3〜0.97em。部品は実測の表で折り・小さくするので図には収まるが、上限いっぱいの札が M・W ばかりだと字が t-xs まで小さくなる。`units` を実測の表に合わせると、作れる札の幅が変わる（書き方の変更）ので、決めていない。
5. **`verify.mjs --overlap` は、文字と線・矢じりの重なりを拾わない。** seq の矢じりは直した。ほかの部品でも、印の札や send の札が線に掛かることはある（文字は隠さないことを写真で見た）。
6. 台本のある場面の左の列（台本より前と後の文）の長さは、台本の検査では見ない。1 画面からはみ出せば verify.mjs のはみ出しで分かる。
7. `fitText` で字が小さくなった札は、隣の箱と字の大きさがそろわない。上限いっぱいの英字の札でだけ起きる（写真の seq の 2 列目など）。
