### 4.3 トークン（第32章）

- `<html>` → `StartTag { tag: "html", self_closing: false, attributes: [] }`。`</head>` → `EndTag { tag: "head" }`。`<p class="first">` → `StartTag { tag: "p", attributes: [Attribute { name: "class", value: "first" }] }`。文字は 1 文字ずつ `Char('M')`。
- `<!doctype html>` を与えると、TagOpen で `!` は英字でないので Data に戻され、`!doctype html>` が Char の列になる（`<` は捨てられる）。パーサの Initial モードがそれを無視する。test.html には doctype が無いので、この話は test2.html の例として書く。
- `<script>` の中身: この版のトークナイザには State::ScriptData 系の 5 状態が定義されているが、Data や TagName からそこへ移る代入が無い（`self.state = State::ScriptData` は 453・465・492 行、どれも ScriptData 系の状態の中）。つまり script の中身も Data 状態で Char の列になり、`</script>` が EndTag になる。中身に `<` が無い限り問題ない（test.html の JS には無い）。HTML Standard では script data 状態に入って `</script>` 以外のタグを文字として扱う。
- 大文字のタグ名・属性名は小文字に直す（`to_ascii_lowercase`）。属性値はそのまま。
- 第32章の担当の確認（2026-11-09）: `enum State` は 18 個（仕様の名前 17 ＋ TemporaryBuffer）。HTML Standard 13.2.5 の tokenizer の状態は 84（2026-11 に数えた）。`Eof` トークンは返らない、と読める（`is_eof()` は `pos > len` だが pos は `input[pos]` を読むときにしか増えず、`pos == len` で読めば添字検査で止まる。終わりは `next()` 冒頭の `None`）。test.html 810 文字 → 543 トークン（StartTag 12・EndTag 12・Char 519）。`TagName` は `' '` だけを見るので改行は名前に入り、`BeforeAttributeName` に空白を飛ばす分岐が無いので `<p  class="x">` は空の Attribute が 1 つ残る、と読める。

### 4.4 DOM の木（第33章）。test.html から saba が作る木（ノード 21 個）

```
Document
└ html
  ├ head
  │ ├ style        └ Text("#title {\n      color: red;\n    }\n    .first { … }\n    …}\n    ")  ← 先頭の改行と空白は入らない
  │ └ script       └ Text("function add(a, b) {\n        return a + b;\n      }\n\n      var target=…;\n      target.textContent=…;\n     ")
  └ body
    ├ h1 [id="title"]     └ Text("My Browser!")
    ├ p  [class="first"]  └ Text("HTML, CSS and JavaScript are working on my browser :)")
    ├ p  [class="links"]  ├ a [href="http://host.test:8000/test1.html"] └ Text("Test page1 ")
    │                     └ a [href="http://host.test:8000/test2.html"] └ Text("Test page2")
    ├ p  [class="hidden"] └ Text("none")
    └ p  [id="target"]    └ Text("original text")
```

- タグの間の改行・空白だけの文字は Text ノードにならない（insert_char は、現在のノードが Text でないときに `'\n'` と `' '` を捨てる。Text ができた後の空白は入る。"Test page1 " の末尾の空白はそのため残る）。
- `<script type="text/javascript">` の属性 type は要素に残る（使われない）。
- 対応している要素は html・head・style・script・body・p・h1・h2・a の 9 種（ElementKind）。title・meta・div などの開始タグは捨てられる（中の文字はスタックの末尾に入る。末尾は Text のこともある）。文字の直後の開始タグは、スタックの末尾の Text の子になる（test.html では起きない。2026-11-14、第33章の仕上げ確認で訂正）。
- Text ノードも stack_of_open_elements に積まれ、終了タグの pop_until で要素と一緒に降りる。

### 4.5 CSS（第34章）。`<style>` の中身から

| 規則 | Selector | Declaration | 当たる要素 | ComputedStyle に入る値 |
|---|---|---|---|---|
| `#title { color: red; }` | IdSelector("title") | color: Ident("red") | h1 | color ＝ Color { name: "red", code: "#ff0000" } |
| `.first { color: #0000ff; }` | ClassSelector("first") | color: HashToken("#0000ff") | p.first | color ＝ Color { name: "blue", code: "#0000ff" } |
| `.hidden { display: none; }` | ClassSelector("hidden") | display: Ident("none") | p.hidden | display ＝ DisplayNone → レイアウトの木に入らない |
| `.links { background-color: #00ffff; }` | ClassSelector("links") | background-color: HashToken("#00ffff") | p.links | background_color ＝ Color { name: "aqua", code: "#00ffff" } |

- トークン列の例: `#title {\n color: red;\n }` → `HashToken("#title")`, `OpenCurly`, `Ident("color")`, `Colon`, `Ident("red")`, `SemiColon`, `CloseCurly`。空白と改行は捨てる。
- 初期値（defaulting）: background_color white、color black、display は body/h1/h2/p が Block・それ以外の要素と Text が Inline・Document が Block、font_size は h1 → XXLarge、h2 → XLarge、他 Medium、text_decoration は a → Underline、height・width 0.0。
- 継承（defaulting）: 親の値が初期値と違うときだけ子に写す（background_color ≠ white、color ≠ black、font_size ≠ Medium、text_decoration ≠ None）。実際の CSS は「color や font は継承し background は継承しない」と性質で決まるが、saba は「初期値と違えば継承」で近似している。
- 当てはめは「規則を書かれた順に上書き」（詳細度も出所も見ない）。
- 第34章の担当の確認（2026-11-09）: style の Text は 171 文字（空白と改行 76 文字）、トークン 31 個（7＋8＋8＋8）、照合は body 以下の要素 8 × 規則 4 ＝ 32 回で true 4 回（Text は 5 個。p.hidden の子は訪ねない）。`from_code` は `#` ＋ 7 文字で、かつ 18 色の符号の表にあるものだけ Ok（`#336699` は Err → color なら black、background なら white）。p.links の background_color aqua は 1 つめの a（a1）とその Text の style にだけ写る。build_layout_tree（layout_view.rs 42 行）は兄弟を親 `&None` で作るので、a2 とその Text は white のまま（2026-11-14、第34章の仕上げ確認で訂正）。paint は Block だけ Rect を出すので見た目は変わらない。

### 4.7 JavaScript（第36章）。`<script>` の中身から

- トークン 37 個: `Keyword("function") Identifier("add") Punctuator('(') Identifier("a") Punctuator(',') Identifier("b") Punctuator(')') Punctuator('{') Keyword("return") Identifier("a") Punctuator('+') Identifier("b") Punctuator(';') Punctuator('}') Keyword("var") Identifier("target") Punctuator('=') Identifier("document") Punctuator('.') - 構文木（Program.body は 3 つ）:
  1. `FunctionDeclaration { id: Identifier("add"), params: [Identifier("a"), Identifier("b")], body: BlockStatement { body: [ReturnStatement { argument: AdditiveExpression { operator: '+', left: Identifier("a"), right: Identifier("b") } }] } }`
  2. `VariableDeclaration { declarations: [VariableDeclarator { id: Identifier("target"), init: CallExpression { callee: MemberExpression { object: Identifier("document"), property: Identifier("getElementById") }, arguments: [StringLiteral("target")] } }] }`
  3. `ExpressionStatement(AssignmentExpression { operator: '=', left: MemberExpression { object: Identifier("target"), property: Identifier("textContent") }, right: AdditiveExpression { operator: '+', left: StringLiteral("Answer? 1 + 2 = "), right: CallExpression { callee: Identifier("add"), arguments: [NumericLiteral(1), NumericLiteral(2)] } } })`
- 評価の筋:
  - 1 → `self.functions` に `Function { id: "add", params, body }` を積む（id は、未定義の Identifier が「その名前の文字列」に評価される規則で `StringLiteral("add")` になる）。
  - 2 → CallExpression: 新しい Environment（outer ＝ 呼び出し側の env）。callee の MemberExpression は object が HtmlElement でないので `"document" + "." + "getElementById"` ＝ `StringLiteral("document.getElementById")`。call_browser_api がこれに一致 → 引数 `"target"` → get_element_by_id → p#target の `Rc<RefCell<Node>>` → `HtmlElement { object, property: None }`。env に `("target", Some(HtmlElement))`。
  - 3 → left の MemberExpression: object は変数 target → HtmlElement、property Identifier("textContent") → 文字列 → `HtmlElement { object, property: Some("textContent") }`。right: `add(1, 2)` → 新しい env に a ＝ 1、b ＝ 2 → Return → `Number(1) + Number(2)` ＝ `Number(3)`。`StringLiteral("Answer? 1 + 2 = ") + Number(3)` → 数どうしでないので文字列の連結 → `StringLiteral("Answer? 1 + 2 = 3")`。property が "textContent" → `object.borrow_mut().set_first_child(Some(Text("Answer? 1 + 2 = 3")))`（元の Text("original text") は外れる）。
- 予約語は var・function・return の 3 つだけ。`check_reserved_word` は先頭一致なので、`variable` のような識別子は `var` ＋ `iable` に割れる（test.html には出てこない）。
- 関数呼び出しの新しい環境の outer は **呼び出し側の env**（定義した場所ではない）。ECMAScript の字句的スコープとは違う、と読める（動的スコープ）。test.html の例では結果は同じ。
- Page::receive_response の順: create_frame（HTML → DOM、CSS → CSSOM）→ execute_js → set_layout_view → paint_tree。**JS は DOM が全部できてから**動く（Chromium は `<script>` でパーサを止める。第10章 場面2 段階4）。
- 最終的な画面（内容領域）: 赤い大きな "My Browser!"、青い "HTML, CSS and JavaScript are working on my browser :)"、水色の帯の上に下線つきの "Test page1 " "Test page2"、黒い "Answer? 1 + 2 = 3"。"none" は出ない。
