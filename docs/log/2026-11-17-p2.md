## 判断（計画からの変更を含む）

- **1画面版の板は、場面の見出しも覆う（場面の領域いっぱい）。** 計画は「場面の本体（左の列と図）を覆う」。見出しを残すと板の中の iframe の高さが約 630px になり、埋め込んだ場面が 0.84 倍に縮んで、1280×688 では本文が約 10px になる。見出しまで覆うと約 740px になり、埋め込みは 1画面版とほぼ同じ大きさ（倍率 0.98 前後）で出る。どの場面の上にいるかは、板の道筋の先頭（「第9章 場面3 システムコール」）で示す。
- **埋め込みの舞台の高さは 736px（`EMBED_H`）。** 上部バー（48px）と場面の見出しを出さないので、本体は 1画面版と同じ高さになる。iframe の幅が 960px 以上・高さ 420px 以上なら 1画面版、それより小さければ縦読み版（板の中の iframe は 1画面版ではいつも約 1570×740 で、倍率の下限 0.76 は当たらない）。
- **板が開いている間は、上部バーの ‹ › と ←→ が一番上の板の段階を動かす。** 板の端では押せない。タブ・↓↑・場面へのリンクで下の場面が動くと、板は全部閉じる。部品の板と埋め込みにも「前へ」「次へ」を出す（埋め込みは上部バーが無いため）。
- **縦読み版の板は画面いっぱいに重ね、ブラウザの「戻る」で 1 段閉じる。** 板が開いている間だけ履歴を 1 つ積み、「戻る」で閉じてまだ板が残れば積み直す。全部を閉じるボタンで閉じたときは、積んだ分を自分で戻す。1画面版は URL の末尾を書き換えて履歴を増やさない方針（P0 以前から）なので積まない。
- **部品の API は、章の場面と同じ `setup(ctx)`・`onStep(ctx, i)`・`frame(ctx, t, dt)` にした。** 計画は `setup(g, params)`。章と同じ形にすると、検証の時刻送り・段階の行き来・文字の重なりがそのまま部品にも使える。印から渡す値は `ctx.params`、部品の中の印は `ctx.mark`。
- **印を出す段階 `steps` は 1 始まり**（URL の `#s3.2` と同じ）。`onStep` の `i` は 0 始まりのまま。
- **重なった下の板は隠す（`hidden`）。** 埋め込みの iframe の動きが止まる。iframe が大きさ 0 になったときは 1画面版と縦読み版を切り替えない（戻ったときに配置が崩れないように）。
- **埋め込みの中のリンクはページ全体で開く**（`<base target="_top">`）。場面へのリンク（`data-go`）だけは iframe の中で場面を移り、道筋も変わる。
- **計画の外に足した印:** 第9章 場面3 段階4 の `sysret` → 部品 段階5。部品の中の「制御装置」→ 第6章 場面1 段階5（解読の板）。
- **部品の注記で FRED に触れた。** Linux 7.1（2026 年）から、FRED を持つ CPU では FRED が既定で使われ、syscall も FRED の入口（IA32_FRED_CONFIG）から入り ERETU で戻る（Phoronix、カーネルの FRED の文書）。第9章 場面3 の「MSR LSTAR に登録された入口へ飛ぶ」は、FRED を使わない多くの x86-64 の PC の説明として残した。
- **事実の出どころ:** SYSCALL・SYSRET・WRMSR は Intel SDM の写し（felixcloutier.com）、IA32_LSTAR = C000_0082H、U/S の規則は SDM Vol. 3A 4.6 の写し（xem.github.io）。

## 部品 cpu-mode の仕上げ確認（別の担当）

担当は「検証済みにしてよい」と報告した。直したのは assets/parts/cpu-mode.js だけで 13 か所。主なもの:

- 照らし合わせの回路（MMU）が CPU の枠の外に描かれていた。第9章 場面4 の「CPU の MMU」と食い違うので、CPU の枠を広げて中に入れた。
- 段階2: WRMSR は EDX:EAX の値を書く（SDM）ので、起動時の wrmsr の間は A = 0x80 にし、制御装置の行を「入口 ← A」にして A → 入口 の矢印を足した（前は A に 45 が出ていて、時期が合っていなかった）。
- 段階3・5: 値を移す矢印を、実行の拍の立ち上がりから出す（前はフェッチの間から出ていた）。段階4: PC は「…」（命令の番地と触れる番地が食い違っていた）。
- 注記の FRED の文を「Linux 7.1 以降の既定で」に弱めた（`fred=off` で無効にできる）。図の説明に「syscall が RFLAGS を r11 に写すなど、x86 のほかの動作は省いた」。段階5 の「M を 0 にするのは…」を「syscall・割り込み・例外など、決まった入口へ飛ぶ仕組みだけ」（SYSENTER やコールゲートもあるため）。
- 同じ情報の 5 重の表示（段階3・5 の where）を消した。frame の書き換えの判定に「立ち上がりを過ぎたか」を加えた（時刻が飛ぶと M・PC の書き換えを落とし得た）。

担当が直さなかったが気になると書いた点（模式として残す）: 実物の SYSCALL はマイクロコードで数十拍かかる（「同じ拍」は YT-8 の模式。図の説明で「ほかの動作は省いた」と書いた）。U/S の線は、ユーザーのページに触れるときもカーネルのページの高さから出ている（実物の U/S はページテーブルの項、TLB から来る）。段階4 で、いまの動作の枠と違反のビットの下の 2 行が同じことを言っている。

担当の指摘で第9章も直した（調整役）:

- 場面1 の印のつなぎの一文「モードは CPU の中の 1 ビットのレジスタ」は、同じ場面の「x86 では ring 0 と ring 3」（CPL は 2 ビット）と食い違うので、「モードは CPU の中のレジスタのビット（x86 は 2 ビットの CPL）」にした。
- 場面3 段階3 の「番号でシステムコール表を引き」は古い。Linux 6.9（2024-04 の Linus のコミット 1e3ad783、BHI 対策。安定版にも移植）から、x86-64 は番号を switch 文（`x64_sys_call`）で振り分け、`sys_call_table` はトレースのためだけに残る。「番号から対応表で sys_recvfrom を選ぶ（Linux 6.9 以降は表を switch 文にして分岐）」にし、段階の一覧の④とまとめの要点 3 を「番号で」に替えた。図の「システムコール表」は番号と関数の対応として残した。
- 場面3 の補足に 1 段落: 図は FRED を使わない多くの x86-64 の PC の道筋。FRED を備えた新しい CPU では、Linux 7.1 以降の既定で入口を IA32_FRED_CONFIG から取り、sysret の代わりに ERETU で戻る。
