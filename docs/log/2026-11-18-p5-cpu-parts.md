## 設計

### mem-read（メモリの読み出し）

params は `addr`（1 か 11。既定 1）。段階の文は 2 通りだけ書き、ほかの値は 1 に寄せる（図だけ変えると文と食い違うため）。中身は第6章の `INIT_MEM`（場面3 の時点なので sum = 0、n = 3）。

| 段階 | 題 | 見せること | addr = 1（既定） | addr = 11 |
|---|---|---|---|---|
| 1 | メモリは 16 行 × 8 列のセルの格子 | 格子・ワード線・ビット線、番地が届く。右にセル 1 個の中（1T1C） | 06 s3.1 の 1 拍め、番地 0001 | 06 s3.4 の 4 拍め、オペランド 1011 |
| 2 | デコーダ：4 本の番地から 16 本のうち 1 本へ | b3〜b0 と ¬b3〜¬b0、行ごとの AND（● が入力）。1 になる AND は 1 個 | 行 1 = ¬b3・¬b2・¬b1・b0 | 行 11 = b3・¬b2・b1・b0 |
| 3 | ワード線が行のセルをビット線につなぐ | VDD の半分のビット線が、1 の列はわずかに上、0 の列は下（差 0.1 V 以下。05 s5.3） | 行 1 | 行 11 |
| 4 | センスアンプが増幅し、データバスへ | 0 か VDD に広げてデータバスへ。同じ増幅で書き戻す（05 s5.3） | 0010 1011 → IR（06 s3.2） | 0000 0011（n = 3）→ ALU の入力 2（06 s3.4） |
| 5 | 上位の番地で、答える部品を選ぶ | 第7章の 0xFEB0_0000：上位 15 ビットの AND が NIC を選び、NAND（b31・b30）の RAM の線は 0。下位 17 ビットが部品の中のレジスタ。実物は BAR | 07 s2.2 | 同じ |

部品の中の印: セル 1 個の中 → 05 s5.1（段階1）、行デコーダの AND → 04 s3.6（段階2）、ビット線 → 05 s5.3（段階3）、センスアンプ → 05 s5.3（段階4）、部品を選ぶ AND → 04 s3.6（段階5）。

### alu（ALU の中）

params は `a`・`b`・`op`（'add' | 'sub'）。既定は 0 + 3。段階の文は第6章の 3 つの例だけを書き、合わない値は op の例に寄せる（`op: 'sub'` で a = b = 1 なら 1 − 1、それ以外の sub は 3 − 1、add は 0 + 3）。

| 段階 | 題 | 0 + 3（既定。06 s3.5） | 3 − 1（06 s4.3） | 1 − 1（06 s4.5） |
|---|---|---|---|---|
| 1 | 入力：A と M、制御信号は加算／減算 | SUB = 0、B = M = 0000 0011、Cin = 0 | SUB = 1、B = 1111 1110、Cin = 1（2 の補数） | 同左（A = 0000 0001） |
| 2 | 右端のビット 0 から決まる | 0 + 1 + 0 = 1 | 1 + 0 + 1 = 10 | 1 + 0 + 1 = 10 |
| 3 | 桁上がりが左へ 1 段ずつ伝わる | 桁上がりは全部 0、和 0000 0011 | ビット 1 は 11、2〜7 は 10、あふれ 1 を捨てて 0000 0010 | 1〜7 は 10、8 段を全部通る、0000 0000 |
| 4 | Z：和の 8 本の OR を NOT する | OR = 1、Z = 0 | OR = 1、Z = 0（JNZ は 0 番地へ） | OR = 0、Z = 1（JNZ は飛ばない） |
| 5 | 次の立ち上がりで A と Z に入る | A ← 0000 0011、Z ← 0（06 s3.5 の 5 拍め） | A ← 0000 0010、Z ← 0 | A ← 0000 0000、Z ← 1 |

部品の中の印: XOR → 04 s3.5（段階1）、全加算器 → 04 s5.4（段階2・3）、桁上がりの遅延 → 04 s6.4（段階3）、OR と NOT → 04 s3.4（段階4）。どれも同じ層（ronri）。

### dec（命令の解読）

params は `op`（'add' | 'sub' | 'jnz'）と `z`（JNZ のときの Z）。既定は ADD 11。命令は第6章のプログラムの ADD 11（1 番地）・SUB 12（4 番地）・JNZ 0（6 番地）で、PC はフェッチで 1 進めた後の値（2・5・7）。ほかの op は ADD に寄せる。

| 段階 | 題 | ADD 11（既定。06 s3.3） | SUB 12 | JNZ 0、Z = 0（06 s4.3） | JNZ 0、Z = 1（06 s4.5） |
|---|---|---|---|---|---|
| 1 | IR の上位 4 ビットだけを解読する | 0010 1011。1011 = 11 番地 → アドレスバス | 0011 1100。12 番地 | 0101 0000。0 番地 → PC の入口 | 同左 |
| 2 | NOT で 8 本の線にする | b5・¬b7・¬b6・¬b4 が 1 | b5・b4・¬b7・¬b6 | b6・b4・¬b7・¬b5 | 同左 |
| 3 | 命令 1 種類に AND を 1 個 | ADD の AND だけ 1 | SUB の AND | JNZ の AND | 同左 |
| 4 | AND の出力が制御信号になる | 番地・読め・ALU ＋・A ← ALU | ALU − のほかは同じ | PC ← 番地（条件つき）だけ | 同左 |
| 5 | JNZ だけは Z と AND を取る | JNZ の線 0 → Load 0、PC = 2 | Load 0、PC = 5 | ¬Z = 1 → Load 1、PC ← 0000 | ¬Z = 0 → Load 0、PC = 7（HALT へ） |

部品の中の印: NOT → 04 s3.2（段階2）、命令ごとの AND → 04 s3.6（段階3）、JNZ と ¬Z の AND → 04 s3.3（段階5）、Z → 部品 alu 段階4（段階5。Z = 1 の例では 1 − 1、ほかでは 3 − 1 を渡す。仕上げ確認で、JNZ（Z = 0）は 3 − 1、JNZ（Z = 1）は 1 − 1、ADD 11・SUB 12 は既定の 0 + 3 の 3 通りにした）。

## 計算で決めた値（計算し直した）

- 0 + 3：0000 0000 + 0000 0011 + 0 = 0000 0011、桁上がりは全部 0、あふれ 0、Z = 0。
- 3 − 1：0000 0011 + 1111 1110（¬0000 0001）+ 1 = 1 0000 0010。桁上がりはビット 0〜7 の全部が 1、あふれ 1 を捨てて 0000 0010 = 2、Z = 0。
- 1 − 1：0000 0001 + 1111 1110 + 1 = 1 0000 0000。桁上がりは全部 1（ビット 0 で生じて 8 段を全部通る）、和 0、Z = 1。
- 命令のバイト：`INIT_MEM[1]` = 0x2B = 0010 1011（ADD 11）、`[4]` = 0x3C = 0011 1100（SUB 12）、`[6]` = 0x50 = 0101 0000（JNZ 0）、`[11]` = 3 = 0000 0011。
- デコーダの AND：行 1（0001）は ¬b3・¬b2・¬b1・b0、行 11（1011）は b3・¬b2・b1・b0。命令は ADD（0010）が ¬b7・¬b6・b5・¬b4、SUB（0011）が ¬b7・¬b6・b5・b4、JNZ（0101）が ¬b7・b6・¬b5・b4。
- MMIO：0xFEB1_FFFF − 0xFEB0_0000 + 1 = 0x2_0000 = 2¹⁷ なので、範囲の中では上位 15 ビット（b31〜b17）が同じ。0xFEB0_0000 >>> 17 = 0x7F58 = 111 1111 0101 1000 で、上から読むと 1111 1110 1011 000（node で確かめた）。RAM の範囲 0x0000_0000〜0xBFFF_FFFF は b31・b30 が 11 でない番地なので、RAM の線 = NAND(b31, b30)。0xFEB0_0000 は b31 = b30 = 1 で RAM の線は 0。

## 事実の出どころ

- 回路と値は教材の章に合わせた（YT-8 は教材の架空の CPU なので外の資料は使わない）：第4章 場面3（NOT・AND・OR・XOR を NAND で、積和形）、場面5（半加算器・全加算器の中）、場面6（リップルキャリー、最悪の場合、2 の補数は反転を XOR・+1 を Cin で）。第5章 場面5（DRAM の 1T1C、VDD の半分のプリチャージ、電荷の分け合い、差 0.1 V 以下、センスアンプの増幅と書き戻し、1 本のワード線に数千セル・列アドレス）。第6章 場面1〜4（命令表、`INIT_MEM`、ADD 11 の 5 拍、22 命令のループの値、図の「DRAM。別のチップ」）。第7章 場面2（NIC の範囲 0xFEB0_0000〜0xFEB1_FFFF、RAM 0x0000_0000〜0xBFFF_FFFF、CTRL +0x00）。
- mem-read 段階5 の「PC はこの形を NIC のレジスタ（BAR）に置き、起動時に決める」（2026-11-18 に確かめた）:
  - Oracle「Writing Device Drivers」の PCI の章（https://docs.oracle.com/cd/E19620-01/805-3024/hwovr-25/index.html）：装置ごとに最大 6 個の 32 ビットの base address register があり、システムのファームウェアが番地を割り当てる。範囲の大きさは 2 のべき乗で、番地はその大きさの倍数にそろえる。ファームウェアは全ビット 1 を書いて読み戻し、大きさを知る。BAR を割り当てる前は装置はデータの読み書きに答えない。→ 大きさが 2 のべき乗でそろえてあるので、範囲に入るかは上位のビットを比べるだけで分かる（段階5 の「上位 15 ビット」の根拠）。
  - Linux の文書（https://docs.kernel.org/PCI/pci.html）：`pci_enable_device()` は、BIOS が割り当てていなければ装置の I/O とメモリの範囲を割り当てる。ドライバは設定空間から番地を読まず、`pci_resource_start()` で受け取る。→「起動時に決める」は、ファームウェア（BIOS）か OS が決める、の意味で書いた。
  - PCI-SIG の仕様書（PCI Local Bus Specification 3.0 §6.2.5）の本文は手に入らず、直接は確かめていない。上の 2 つの範囲だけを書いた。RAM の側の境目（0xC000_0000）が実物ではどこで決まるか（Intel の TOLUD などの CPU 側のレジスタ）は確かめていないので、部品には書いていない（図は第7章の地図どおりの NAND の模式）。

## 模式にした所

- mem-read：1 番地 = 1 行（実物は 1 本のワード線に数千セルで、列アドレスで選ぶ。注記に書いた）。ビット線は列ごとに 1 本で描いた（第5章 場面5 と同じ描き方）。ビット線の電圧を h の濃さで描き、段階3 の差は誇張した（凡例に書いた）。行デコーダの AND は 1 本の横線と ● で 4 つの入力を描いた（16 行に 4 本ずつの線を引くと読めないため）。段階5 の NIC の選択は、決め打ちの AND の模式（実物は BAR と比べる回路。図と本文に書いた）。
- alu：8 ビットで加算と減算だけ（注記に書いた）。桁上がりの確定は「右隣の桁上がりが決まってから」の形で描き、0 + 3 の段階3 の本文で「として描いた」と断った（ゲートの段では、A と B がともに 0 の桁は桁上がりを待たずに 0 を出すので、0 + 3 は実際には 8 段を待たない）。段階5 は A の出力が入力 1 へ戻る線を描いていない（取り込む瞬間だけを見せる）。
- dec：合図を何拍めに出すかと、全命令に共通のフェッチの合図を省いた（注記）。JNZ の条件は、第6章の板（Z を AND の入力に足す）と違い、JNZ の AND の出力と ¬Z の 2 入力 AND に分けて描いた（論理は同じ。差し込みの「JNZ の線 AND ¬Z」の形）。

### 事実と値の確かめ

- BAR: Oracle「Writing Device Drivers」の PCI の章（docs.oracle.com/cd/E19620-01/805-3024/hwovr-25）を読み直した（2026-11-18）。システムのファームウェアが番地を割り当てること、範囲の大きさは 2 のべき乗で先頭はその大きさにそろえること、BAR を割り当てる前は装置がデータの読み書きに答えないことが書いてある。Linux の文書（docs.kernel.org/PCI/pci.html §1.4.1）の「BIOS が割り当てていなければ pci_enable_device() が割り当てる」も確かめた。部品の言い方（パソコンはこの並びを NIC の BAR に置き、起動時に決める）は資料の範囲に収まる。
- RAM の上端（第7章の図の 0xBFFF_FFFF）を実物で決める CPU 側のレジスタ（Intel の TOLUD）は、検索の要約では「BIOS が書き、その値より下の番地を DRAM に回す」だが、データシートの本文を読めなかったので部品に書いていない（図の説明で「第7章の図の番地の模式」とした）。
- 計算し直した値（node）: 0xFEB0_0000 >>> 17 と 0xFEB1_FFFF >>> 17 はどちらも 111 1111 0101 1000（上から 1111 1110 1011 000）、範囲は 2¹⁷ で先頭は 2¹⁷ の倍数。b31・b30 は 0xBFFF_FFFF で 10、0xC000_0000 と 0xFEB0_0000 で 11。命令 0x2B・0x3C・0x50 のビット。3 − 1 = 1 0000 0010、1 − 1 = 1 0000 0000。
- 第6章の値との突き合わせ: INIT_MEM と部品の MEM、TRACE の 1 周め・3 周めの A と Z（ADD 11 の前の Z はリセットの 0、1 周めの SUB 12 の前は ADD 11 の 0 + 3 で 0、JNZ の前は SUB 12 の結果）、フェッチ後の PC（2・5・7）、06 s3.1〜s3.5・s4.3・s4.5 の本文と図の値。
- 0 + 3 の桁上がり: 全加算器の Cout = A·B + Cin·(A⊕B) なので、A = B = 0 の桁は Cin によらず 0。ビット 1 の桁上がりだけがビット 0 を待つ（作った担当の記録のとおり）。

### 直さなかったが気になる点

- alu の段階5: A が取り込んだ後も、図の入力 A は 0000 0000 のまま（A の出力が入力 1 へ戻る線を描いていない）。取り込む瞬間の模式として残した（作った担当の判断どおり）。
- alu の印「桁上がりの遅延」は、あふれの矢印に付けてある（札は左端の B の文字の下）。名前と要素が少しずれるが、重なりは無い。
- dec の home は 06-cpu.html#s1。同じ ADD 11 の解読の板は 06 s3 段階3 にもある。どちらでもよいのでそのまま。
- 06 s3.2 に足す印の札は、YT.zoom の板（PC + 1）が開くまでの 2.4 秒しか出ない（作った担当の記録のとおり。一覧からは開ける）。

### 章で直したほうがよい所（作った担当の 3 件への意見。章は変えていない）

1. buildDEC の JNZ のオペランド: 指摘は正しい。`opTxt` は JNZ でも「→ そのままアドレスバスへ（解読しない）」と出し、アドレスバスへの線（`bus`）も光らせる。同じ板の合図の表は JNZ の「PC ← 番地」に ● を付けているので、板の中で食い違う。場面1 段階5 の板は 8 命令を 4.2 秒ずつ巡るので、動かしている人には 25〜29 秒めに出る（止めた人には ADD 11 の姿だけが出る）。直すなら JNZ のときだけ「→ PC の入口へ（飛び先）」にし、アドレスバスへの線を光らせない。
2. 第7章 場面2 段階2「配線によって」: 指摘は正しい。同じ場面の補足が「PCIe 装置のレジスタの範囲（BAR）は起動時にファームウェアと OS が決めて割り当てる」と書くので、場面の中で食い違っている。図の札「配線で装置へ」（`st.wireTxt`）と図2 の説明「物理アドレス空間（中央）の一部が装置のレジスタに配線されている」も同じ言い方なので、直すなら 3 か所。
3. 06 s3.5 の P4 のつなぎの一文と buildALU の 0 + 3: 一文の「0 + 3 も…右から 1 段ずつ伝わって確定する」はゲートの段では言い過ぎ（0 + 3 は 2〜3 段で決まる）。ただし表のとおり部品 alu に張り替えれば、この一文は消える。板の 1 桁ずつの動きは第4章 場面6 と同じ「右隣を待つ」模式で、板の説明「桁上がりは右（ビット 0）から左へ 1 段ずつ伝わる」も作りの話なので、そのままでよい。
