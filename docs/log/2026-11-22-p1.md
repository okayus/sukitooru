## P1 の並走

コミット `153ae67`。Worker のコードは持たず、リポジトリの root を静的アセットにした。

| 決めたこと | 中身 | 理由 |
|---|---|---|
| `html_handling` | `none` | 既定は `/x.html` を `/x` へ 307 で転送し、engine.js の章の判定が外れる |
| ディレクトリの URL | `_redirects` で `/` と `/news/` だけ index.html を 200 で返す | `none` ではディレクトリの URL が index.html を返さない（Cloudflare の文書の表） |

確かめたこと:

- learning-loop.md §8 の 2 つを解いた。静的アセットのディレクトリにリポジトリの root（`"."`）を指定できる。`none` のとき `/` は index.html を返さないが、`_redirects` の 200 で返せる。wrangler は `_redirects`・`_headers`・`.assetsignore` を、`.assetsignore` の中身にかかわらずアセットから外し、`_redirects` をディレクトリから直接読む（wrangler 4.125.0 の cli.js）。
- 手元の wrangler dev と新しい URL の両方で、`/`・`/news/`・`.html` が 200、`/chapters/01-denshi`・docs/・tools/・.git/・news/*.md・wrangler.jsonc・_redirects が 404。
- `node tools/verify.mjs --base https://sukitooru.shiraoka.workers.dev/` で全 60 ページ（目次・用語索引・部品の見本・36 章・ニュース 21）が ✓。
- 既定の `html_handling` で立てた wrangler dev では、`--base` が 09-os.html の転送と、リンク 4 本の 307 を失敗として出した（新しい検査が罠を拾う）。

## Workers Builds の接続（Claude in Chrome、持ち主の許可で）

okayus-skills の cloudflare-workers-builds-keyless-deploy（0.4.2）の手順と違った所。静的サイトの版として skill に還元するときの材料。

- Worker の設定 → ビルドの「Git リポジトリ」の欄に、「接続」ではなく GitHub・GitLab・配信元のボタンが出た。GitHub を押すと GitHub のアプリの導入先選び（`installations/select_target`）に飛び、導入済みの okayus は「Configure」（導入の設定）にしか行けず、Cloudflare に戻らない。
- 原因は、GitHub のユーザーの認可（Authorized GitHub Apps）に Cloudflare Workers and Pages が無かったこと。導入（Installed GitHub Apps、All repositories）とは別で、Cloudflare の文書は「つなぐ人ごとに一度」要るとする。Workers & Pages → 作成 →「Connect GitHub」で `login/oauth/authorize` に行き、Authorize（持ち主の許可を得て押した）の後は、Worker の欄に「接続」が出た。
- 接続のダイアログ: リポジトリの初期値は一覧の先頭（obsidian-memo）で、Worker の名前からは選ばれない。「ビルドを無効化」の切り替え、「プレビューコマンド」（`npx wrangler preview`）、「プレビュービルドを有効化」（初期値は on）がある。API トークンの初期値は別のプロジェクトのもの（matatabetai Workers Builds）で、「新しいトークンを作成する」は一覧の先頭。名前の初期値 `Workers Builds - YYYY-MM-DD HH:MM` を `sukitooru Workers Builds` に書き換えた。
- 生成されるトークンの権限（画面の表示）: Account Settings 読み、Workers Scripts・KV・R2・D1・Vectorize・Queues・Basin Pipelines・Containers・Cloudchamber・AI Search 編集、Connectivity Directory 読みと bind、全ゾーンの Workers ルート編集、ユーザーの詳細とメンバーシップの読み。
- 接続の後の設定の画面は「プロダクション」と「プレビューのベース」のタブに分かれ、プレビューのベースに「プレビューブランチのビルド」の切り替え（off）がある。
- dash.cloudflare.com では、Claude in Chrome の find・read_page が「Permission denied for reading pages on this domain」で使えず、写真と座標で操作した。
- 接続の後の最初の push（`440b3da`、docs/ だけのコミット）でビルドが起動し、10:30:44Z にデプロイした（`wrangler deployments list` の Source は Unknown (deployment)）。check-run `Workers Builds: sukitooru`（cloudflare-workers-and-pages）は success。GitHub Pages のビルドも同じコミットで動いた。
