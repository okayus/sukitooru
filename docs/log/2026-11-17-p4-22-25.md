- **縮小 → 第24章 場面5（横・例が違う）。** 補足が「縮小は第24章 場面5の拡大と同じ考えの補間」と書いている。拡大と縮小は向きが逆なので「例が違う」。教材に縮小の説明は無い。
- **ラック 4 → 同じ章の場面6 段階2。** 「ラックの電源やスイッチが止まると数十台が同時に消える」は、ラックの機械が ToR 1 台を通って網につながることに頼る。それを図で見せるのは場面6 段階2（ToR）だけ。登録簿では同じ層になる。
- **ISP の道の選び方 → 第16章 場面2 段階3（例が違う）。** 下は「Google 直結と上流経由」の 2 候補を LOCAL_PREF と AS_PATH の長さで選ぶ例。上は 3 つの拠点が同じ AS_PATH で広告し、近さ（IGP のコスト）で決まる。近さで決める段は下の段階に無いので、「例が違う」にして P5 の候補に入れた。第17章 場面5 段階5（Anycast）は上と同じ抽象（「経路の上で最も近い 1 か所に届く」）で止まるので選ばなかった。
- **Maglev のハッシュ → 第27章 場面3 段階2（横）。** 下の段階の本文が「Maglev の GFE 選び（第22章 場面3）も同じ考え」と書いている。登録簿で配信の下に「データ構造とアルゴリズム」は無いが、使っている仕組みそのもの。下の例は MAC の末尾のバイトを 8 で割る表で、5 つ組ではない（例が違う）。

### 判断（第23章）

- **第23章が頼る下の層は、数をビットで持つこと（第4章）、計算とメモリ（第6章）、画素と PCM の形（第8章）に限られる。** DCT・量子化・符号は数学で、その場面の中で説明し終えている。目と耳の性質（場面1 段階3、場面6 段階2）は計算機の層ではないので数えなかった。場面5 は PSNR の 255 の 1 本だけにした。
- **第8章への印 5 本は「横」。** 登録簿で動画の圧縮（codec）の下は CPU だけで、画面と音（display）が無い。圧縮の入力は第8章の画素の数値と PCM なので、依存としては下の層。登録簿の codec の down に display を足すかは「他の章で直したほうがよい所」に書いた。第26章（型）への 1 本も「横」。
- **場面2 段階1 → 第8章 場面1 段階3。** ブロックを取り出すには、1 本の列のメモリから行ごとに幅の分ずつ離れた所を読む。第27章 場面1 段階1（配列）も候補だったが、画素の 2 次元の並びを番地の式で示すのは第8章。下はフレームバッファ（RGB で 1 画素 4 バイト）で、上は Y' の面（1 画素 1 バイト）なので「例が違う」。

- **場面6 は、同じ章の場面2・4・5 への印を 4 本張った。** 全体の時間軸の行（接続・配信元へ・断片・最初の画）を押すと、その区間を拡大した場面を板で開ける。章の札（表紙へのリンク）とは役目が違う。層の登録簿では場面2（HTTP・TCP・TLS）と場面4（TCP・IP）は場面6（ブラウザ・ストリーミング）の下に当たる。
- **「横」3 本:** 場面2 段階5 と場面3 段階5 の第22章（サーバーの中・Maglev。配信の層は HTTP・TCP の上で、登録簿の下に無い）、場面4 段階6 の第24章 場面2（ストリーミングは TCP・IP の上）。どれも上の本文が指す章で、その区間で働く仕組みそのもの。
- **「同じ層」9 本:** 第25章の場面は扱う章の層に振り分けてあるので（layers.js の '25-1'〜'25-6'）、その章への印は同じ層になる（名前の往復 → 第17章、経路表 → 第16章 など）。
- **例が違う 3 本:** NAT の 2 本（第14章 場面4 は QUIC の 51234 → 40001、上は TCP の 51235 → 40002）と、輻輳制御（第19章 場面4 は TCP の 10 個から 1 往復ごとに倍、上は QUIC の 1,250 B のデータグラム 約 1,400 個）。
