## 仕事

## 印の書き方（P4 と同じ）

```js
// 場面の setup の中、印を付ける要素を作った後に、1 行に 1 つ
YT.drill.mark(st.kQueue, { part: 'nic-rx', step: 5, label: '受信キュー', at: [404, 492], steps: [3], bridge: '受信キューのデータは、NIC が DMA で書いた 1,452 B の断片' });
```

- 1 行に 1 つ。第 1 引数はカンマを含まない式。第 2 引数は文字と数の値だけの対象（`params: { via: 'quic' }` も値だけ）。ループや関数の中で作らない。
- steps は 1 始まり。1 つの段階に出る印は 3 つまで。at は必ず書く（札は 26×22px。文字・ほかの札・動く札の止まる位置に重ねない）。bridge は 60 字まで、label は 20 字まで。
- 変えないもの: 段階の文・段階の数・場面の構成・図。変えてよいのは印の行と、印を付けるために要素を変数に持たせる所だけ。本文の誤りは直さずに記録と報告に書く。

## 検証（完了の条件）

章ごとに:

1. `node tools/drillcheck.mjs --list chapters/NN-*.html` — 印の無い場面・注意が無い。部品への印の向きが「下」か（「同じ層」「横」なら理由を記録に）。
2. `node tools/xrefcheck.mjs chapters/NN-*.html` — 問題 0 件（部品の名前と step の範囲も見る）。
3. `node tools/lencheck.mjs chapters/NN-*.html` — 印の行の超過が無い。
4. `timeout 900 node tools/verify.mjs --nav --overlap --drill chapters/NN-*.html` — ✓。文字の重なりの注意が増えていない（前からあるのは第2章 場面6 の 9 件と第1章 場面1 段階4 の乱数だけ）。掘り下げの ✗ が無い。
5. 写真: `timeout 900 node tools/verify.mjs --shots <一時置き場>/shots --all-steps --drill chapters/NN-*.html` で、張った・張り替えた印のある段階の写真と、開いた部品の板（1920 幅と縦読み版）を見る。札がどの要素の印か分かる位置か、重なっていないか。板の部品が、つなぎの一文が言う段階で開いているか。

## 守ること

- 変えてよいのは、受け持つ章のファイルと自分の記録のファイルだけ。assets/（部品を含む）・tools/・parts.html・index.html・ほかの章・ほかの docs は変えない。
- ほかの担当が同時にほかの章に印を張っている。`--drill` で開いたほかの章の埋め込みにエラーが出たら、少し待って走らせ直す。
- tools/serve.sh は使わない。verify.mjs は `timeout 900`、shot.mjs は `timeout 300` を付ける。Chrome のプロセスを名前で止めない。
- 写真と一時ファイルは一時置き場にだけ置く。
- サブエージェントを呼ばない。git の commit・push をしない（調整役がする）。
