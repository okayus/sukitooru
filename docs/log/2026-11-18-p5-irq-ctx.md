## 設計

### irq-entry（割り込みの入口）

部品 cpu-mode と同じ YT-8 の模式（CPU の枠の中に制御装置・レジスタの列、右にメモリ）。レジスタの位置は cpu-mode と同じで、A（rax）→ SP、戻り先（rcx）→ FLAGS の IF、入口（LSTAR）→ IDTR に置き換えた。CPU の右の列に受け付けの判定（INT AND IF）とローカル APIC、CPU の下に外の装置（キーボード → I/O APIC、IRQ1）と、syscall（部品 cpu-mode）との比べの表（合図・入口・戻り先・戻る の 4 列。段階ごとにその列を x で示す）。段階2・3 の順（IDT を読んでから積む）は仕上げ確認で SDM の擬似コードの順に入れ替えた（下の「仕上げ確認」）。

| 段階 | 題 | 見せること（key） | timer で変わる所 |
|---|---|---|---|
| 1 | 命令の切れ目で INT と IF を見る | キー A → IRQ1 → ローカル APIC がベクタ 33 を用意して INT = 1。i7（mul）を終えた切れ目で INT AND IF = 1 → 受け付け。i8 は取り出さない（PC = 0x27 のまま） | APIC の中のタイマがベクタ 236 で INT = 1。装置の箱は薄く |
| 2 | IDT の 33 番から入口を読む | IDTR + 33 × 16 = 528 バイト先 → 入口 0xB0。M = 1 のまま読む（割り込みの手順の IDT・TSS の読み出しは CPL によらずカーネルの読み出し） | 236 × 16 = 3,776 → 0xBA |
| 3 | スタックを替えて積み、入口へ飛ぶ | M = 1 → 0 なので SP ← 0xE0（TSS の RSP0）。0xDF ← SP 0x78、0xDE ← FLAGS（IF = 1）、0xDD ← M = 1、0xDC ← PC 0x27。SP = 0xDC。次の拍で PC ← 0xB0、M ← 0、IF ← 0。「ここまで約 1 µs（第7章）」 | 入口 0xBA |
| 4 | ハンドラが装置と話す（timer は「タイマの処理」） | 入口のコードが汎用レジスタを 0xDB に積む（CPU の 4 つと合わせて pt_regs）。スキャンコードを読みキューへ → EOI（第7章の順） | EOI を先に書き（Linux の sysvec_apic_timer_interrupt の順）、時刻と消費時間を進める。取り分は残る |
| 5 | iretq でスタックから戻す | 汎用を戻す → 0xB6 の iretq（48 CF）→ 0xDC〜0xDF を積んだ逆の順に読む → PC ← 0x27、M ← 1、IF ← 1、SP ← 0x78。i8 から続く | iretq は 0xC0。同じタスクが 0x27 から続く |

- 止めたときの姿: 段階1 は受け付けた瞬間（INT・IF・受け付け = 1、制御装置の 1 行め）、段階2 は IDT の行を読んだ後（IDTR と IDT の行を x）、段階3 は 4 つを積んで入口に飛んだ後（PC・M・IF を x）、段階4 は EOI の後、段階5 は戻った後（PC・M・IF・SP を x、スタックの 5 段は薄い字で残す。メモリの中身は消えないため）。
- 動き: IRQ1 の e の粒（キーボード → APIC）、番地・中身の札（積むときは CPU → メモリ、読むときはメモリ → CPU）、クロック（段階3・5 で e）。
- 部品の中の印（8 個。1 段階 3 つまで）: ローカル APIC → 07 s3.3（段階1）、受け付けの AND → 04 s3.3（段階1）、比べる表 → 部品 cpu-mode 段階3（段階1〜3）、IDT の読み出し → 06 s1.4（段階2。部品 mem-read ができたので張り替え候補。下の表）、スタックへの書き込み → 06 s1.4（段階3）、M → 05 s2.3（段階3・5）、SP → 05 s3.5（段階5）、比べる表 → 部品 cpu-mode 段階5（段階5）。段階4 には印を置かなかった（EOI は xAPIC なら MMIO、x2APIC なら MSR への書き込みで、行き先を 1 つに決められない）。

### ctx-switch（タスクの切り替え）

左に CPU（PC・M・SP・CR3・汎用レジスタの 5 つと、いまの動作）、右にメモリ（上にコア 0 のランキュー、その下に A と B の列。列ごとに task_struct（thread.sp と交代の印 need_resched）・カーネルのスタック 7 段・ページテーブル・ユーザーのコード）。段階5 で SP → A.thread.sp と B.thread.sp → SP の矢印、段階4 で B の表 → CR3 の矢印が出る（動いている間は値の札がその上を動く）。

| 段階 | 題 | 見せること（net） | comp で変わる所 |
|---|---|---|---|
| 1 | タイマ割り込みで A のスタックに積む | A（レンダラ メイン、PID 4188）の 0x27 の手前で割り込み。0xDF〜0xDC に SP・FLAGS・M・PC（CPU）、0xDB に汎用（入口のコード）。PC ← 0xBA、M ← 0、SP = 0xDB | 同じ |
| 2 | 取り分を使い切ったら印を立てる | vruntime 120.0 → 123.0（3 ms）、A の need_resched = 1。PC = 0xBE（irq-entry の timer の「時刻と消費時間を進め…」の行） | 同じ |
| 3 | schedule() が次のタスク B を選ぶ | 呼ぶときに戻り番地を 0xDA に積む（SP = 0xDA）。ランキューで vruntime 最小のネットワーク 118.2 を選ぶ。A は実行可能へ、need_resched を消す | ネットワークは待ち（S）。合成スレッド 121.5 を選ぶ |
| 4 | CR3 を B の表に替える | switch_mm_irqs_off：CR3 4188 の表 → 4133 の表 | 題「CR3 は替えない（同じプロセス）」。両方の表を x、CR3 はそのまま |
| 5 | SP を入れ替える（switch_to） | rbx・rbp・r12〜r15 を 0xD9 に積む → A.thread.sp ← 0xD9 → SP ← B.thread.sp = 0xC9 → B の 6 個を取り出す（SP = 0xCA、汎用 = カーネル（B）） | 同じ |
| 6 | B のスタックから B の続きへ | 戻り番地（0xCA）→ 0xCB、汎用（0xCB）→ 0xCC、iretq が 0xCC〜0xCF を読む → PC ← 0x43、M ← 1、SP ← 0x5C。B のユーザーのコードの行を x | 同じ |

- 止めたときの姿は各段階の終わり（段階5 は両方の矢印と A.thread.sp = 0xD9・SP = 0xCA、段階6 は PC・M・SP を x）。
- 部品の中の印（4 個）: A のスタック → 部品 irq-entry 段階3（timer）（段階1）、CR3 → 09 s4.2（段階4。部品 mmu-walk の段階2 が張り替え候補）、SP → 05 s3.5（段階5）、B のスタック（iretq）→ 部品 irq-entry 段階5（timer）（段階6）。段階2・3 は印なし（vruntime と選ぶ規則の下は第9章 場面5 段階4 と第27章で、どちらも部品から見て下でない）。

### 例の値と出どころ

| 値 | 出どころ |

| M（1 = ユーザー、0 = カーネル）、番地を 8 ビットに縮めた模式、syscall の入口 0x80・sysret 0xF0、戻り先は rcx、入口は LSTAR | 部品 cpu-mode |
| 番地の割り当て（下の表） | この 2 つの部品で決めた（cpu-mode の 0x10〜0x1D・0x80〜0xAF・0xF0 と重ねない） |

番地の割り当て（8 ビットの模式。1 番地に 1 つの値を積む）:

| 番地 | 中身 | 部品 |
|---|---|---|
| 0x26・0x27 | i7 mul・i8 store（第7章の命令の列。i_k を 0x1F + k に置いた）。timer と ctx-switch では A（レンダラ メイン）の実行中の命令と次の命令 | irq-entry・ctx-switch |
| 0x43 | B の次の命令（B のユーザーの番地） | ctx-switch |
| 0x5C・0x78 | B・A のユーザーのスタックの上端（SP） | ctx-switch・irq-entry |
| 0xB0〜0xB7 | キーボードのハンドラ（0xB0 入口、0xB2 キーコード、0xB4 EOI と汎用を戻す、0xB6 iretq） | irq-entry |
| 0xBA〜0xC1 | タイマのハンドラ（0xBA 入口、0xBC EOI、0xBE 時刻と消費時間・汎用を戻す、0xC0 iretq） | irq-entry・ctx-switch |
| 0xC8〜0xCF | B のカーネルのスタック（底 0xD0） | ctx-switch |
| 0xD8〜0xDF | A（irq-entry では割り込まれたプログラム）のカーネルのスタック（底 0xE0） | irq-entry・ctx-switch |

計算:

- IDT の行の位置: 64 ビットモードの IDT は 1 行 16 バイトなので、33 × 16 = 528（0x210）、236 × 16 = 3,776（0xEC0）。0xEC = 14 × 16 + 12 = 236。
- 積む順（SDM の擬似コードの SS・RSP・RFLAGS・CS・RIP を、SS を除き CS を M として 1 番地ずつ。IDT の行は積む前に読み、CPL は積んだ後に変わる）: 底 0xE0 から 1 ずつ減らして書く。0xDF ← SP、0xDE ← FLAGS、0xDD ← M、0xDC ← PC で SP = 0xDC。入口のコードの汎用で 0xDB。iretq は積んだ逆の順に 0xDC（PC）・0xDD（M）・0xDE（FLAGS）・0xDF（SP）を読む。
- ctx-switch の A: 0xDB（汎用）の上に schedule() を呼んだ戻り番地 0xDA、__switch_to_asm の 6 個 0xD9 → thread.sp = 0xD9。B: thread.sp = 0xC9 → 6 個を取り出して 0xCA → 戻り番地で 0xCB → 汎用で 0xCC → iretq で 0xCC〜0xCF を読み、SP ← 0x5C。
- iretq は 2 バイト（REX.W + CF = 48 CF）なので、フェッチ後の PC は 0xB8（key）・0xC2（timer）。どちらも図に出る番地と重ならないように、タイマのハンドラを 0xBA から置いた（最初は 0xB8 から置き、key の段階5 で PC = 0xB8 がタイマの入口に見えた）。
- vruntime: nice 0（重み 1024）なので 3 ms 走ると 120.0 + 3 × 1024 / 1024 = 123.0。第9章 場面5 の `ranUntil` と同じ。

## 事実の出どころ（2026-11-18 に確かめた）

Intel SDM:

- Vol. 2「INT n/INTO/INT3/INT1」の Operation（https://www.felixcloutier.com/x86/intn:into:int3:int1 。SDM の写し）: この擬似コードは外部割り込み・NMI・例外にも当てはまる。IA-32e モードでは IDT の行は vector « 4 の位置の 16 バイト。特権が下がる（CPL 3 → 0）ときは新しい RSP を TSS から読み（IST が 0 なら RSP0）、RSP を 16 バイトにそろえ、元の SS・RSP、RFLAGS、CS・RIP（、エラーコード）の順に 8 バイトずつ積む。CPL ← ゲートの DPL。割り込みゲートなら IF ← 0。
- Vol. 2「IRET/IRETD/IRETQ」（https://www.felixcloutier.com/x86/iret:iretd:iretq ）: 64 ビットのオペランドでは RIP・CS・RFLAGS を取り出し、外側の特権へ戻るときは RSP・SS も取り出す。
- Vol. 3A 6.6「Program or Task Restart」（https://xem.github.io/minix86/manual/intel-x86-and-64-manual-vol3/o_fe12b1e2a880e0ce-191.html ）: 割り込みは必ず命令の切れ目で受け付ける。保存する戻り先は、その切れ目の次の命令。
- Vol. 3A 6.8.1（…-192.html）: IF は INTR 端子とローカル APIC から来るマスクできる割り込みを止める。NMI と INT 命令は止めない。
- Vol. 3A 6.14.1〜6.14.4（…-203.html・…-204.html）: 64 ビットモードでは IDT の番号を 16 倍して引く。積むのは常に 8 バイトで、SS:RSP は特権が変わらなくても積む。TSS から読むのは内側の RSP だけ。IRET は 64 ビットモードでは SS:RSP を必ず取り出す。

Linux（torvalds/linux の master、2026-11-18 時点で 7.4-rc3。https://github.com/torvalds/linux/blob/master/ の下のパス。一部は git.kernel.org から同じ版を読んだ）:

- `arch/x86/include/asm/irq_vectors.h`: `LOCAL_TIMER_VECTOR 0xec`、`FIRST_EXTERNAL_VECTOR 0x20`、`ISA_IRQ_VECTOR(irq)`（0x30 + irq）。
- `arch/x86/kernel/irqinit.c`・`arch/x86/kernel/apic/vector.c`: 起動時に ISA の IRQ 0〜15 を 0x30 + irq に置くが、IO-APIC が受け持つと（動いているタイマ以外は）手放して、割り当て直す。キーボードの番号は決まっていない。
- `arch/x86/kernel/idt.c`: ローカル APIC タイマは `INTG(LOCAL_TIMER_VECTOR, asm_sysvec_apic_timer_interrupt)`、装置の番号は `set_intr_gate` で `irq_entries_start` の入口へ（どちらも割り込みゲート）。`arch/x86/include/asm/idtentry.h`: `irq_entries_start` の入口は番号を積んで `asm_common_interrupt` へ。
- `arch/x86/entry/entry_64.S`: `idtentry` → `error_entry`（`PUSH_AND_CLEAR_REGS`、ユーザーからなら `swapgs`・`SWITCH_TO_KERNEL_CR3`、`sync_regs` で「本当のスレッドのスタック」へ）。戻りは `common_interrupt_return`（`POP_REGS`、PTI なら iret の枠を trampoline に写して CR3 を戻す、`iretq`）。`__switch_to_asm`（rbp・rbx・r12〜r15 を積み、`movq %rsp, TASK_threadsp(%rdi)`、`movq TASK_threadsp(%rsi), %rsp`、取り出して `jmp __switch_to`）。
- `arch/x86/entry/calling.h`: `PUSH_REGS` が汎用レジスタ 15 個を pt_regs に積む。`arch/x86/include/asm/ptrace.h`: pt_regs の末尾が IRETQ の枠（ip・cs・flags・sp・ss）。
- `arch/x86/kernel/cpu/common.c`: 「sp0 points to the entry trampoline stack regardless of what task is running」（64 ビット）。`fred=off` で FRED を止められる。FRED のときは IDT を読み込まない。
- `arch/x86/entry/entry_fred.c`: FRED では外部割り込みを番号で振り分ける（システムの番号は `sysvec_table`、ほかは `common_interrupt`）。
- `arch/x86/kernel/apic/apic.c`: `sysvec_apic_timer_interrupt` は `apic_eoi()` を先に呼び、次に `local_apic_timer_interrupt()`。
- `kernel/irq/chip.c` の `handle_edge_irq`: ハンドラの前に `irq_ack`（x86 のベクタの層では `apic_ack_edge` → `apic_eoi`）。エッジの割り込みでは EOI が先。
- `kernel/sched/fair.c`: `update_curr` が vruntime を足し、`update_deadline` が取り分（slice）を使い切ったら真 → `resched_curr_lazy`。`kernel/entry/common.c`: ユーザーへ戻る手前のループで `_TIF_NEED_RESCHED(_LAZY)` なら `schedule()`。
- `kernel/sched/core.c`: `__schedule` は `pick_next_task` の後に `clear_tsk_need_resched(prev)`。`context_switch` は `switch_mm_irqs_off` の後に `switch_to`（「Here we just switch the register state and the stack.」）。
- `arch/x86/mm/tlb.c` の `switch_mm_irqs_off`: `prev == next`（同じ mm）なら CR3 を書かない（「switching from one thread in a process to another thread in the same process. No TLB flush required.」）。
- `arch/x86/include/asm/switch_to.h`: `inactive_task_frame`（thread.sp が指す枠。r15〜r12・bx・bp・ret_addr）。`arch/x86/kernel/process_64.c` の `__switch_to`: FPU（`switch_fpu`）、fs・gs のベース（`save_fsgs`）、`current_task` と `cpu_current_top_of_stack` を次のタスクに。
- `include/uapi/linux/input-event-codes.h`: `KEY_A 30`（下の「章で直したほうがよい所」）。
- FRED が Linux 7.1 以降の既定であることは部品 cpu-mode の確かめ（Linux 7.1 のコミット「x86/fred: Enable FRED by default」）に従った。

## 模式にした所

- 番地は 8 ビット、積む値は 1 番地に 1 つ（実物は 8 バイトずつ）。SS は積む図から省き、CS を M（CPL）として積む（注記に書いた）。
- CPU が積む先は「カーネルのスタック（底 = TSS の RSP0）」に縮めた。Linux（FRED でない 64 ビット）では TSS の RSP0 は CPU ごとの trampoline スタックで、入口のコードがタスクのスタックへ写す（図の説明に書いた）。ctx-switch の段階5 の「次の割り込みで積む先も B のスタックにする」は、`__switch_to` が `cpu_current_top_of_stack` を替えることを指す。
- 受け付けを INT AND IF の 2 入力にした。実物は APIC の優先度（TPR・PPR）、STI・MOV SS の直後の 1 命令、NMI もある。PC ← 入口・M ← 0・IF ← 0 を「次の拍で同時に」は YT-8 の模式（cpu-mode と同じ）。
- IDT は 8 ビットの番地に置かず、表として描いた（IDTR の値は「IDT」）。
- PTI（ページテーブルの分離）を使う CPU で入口と出口に起きる CR3 の切り替えは描かない。
- ハンドラの行はコードのまとまりで、番地はまとまりの先頭。
- ctx-switch: pt_regs と switch の枠の間のカーネルの呼び出しの跡を「戻り番地（割り込みの出口へ）」1 段に、__switch_to_asm の 6 個を 1 段にまとめた。B も前に同じ道（タイマ割り込み → schedule()）で止まったと置いた（待ちから起きたタスクなら、戻る道は syscall の出口になる）。次のタスクは第9章 場面5 段階4 の規則（vruntime 最小）で選んだ（6.6 以降の EEVDF は締め切りも見る。第9章 段階4 の本文が書いている）。FPU と fs・gs のベースは描かない（注記に書いた）。

## 迷った所と決め方

1. **層はどちらも cpu。** irq-entry は CPU のハードウェアの動き（命令の切れ目・積む・IDT・iretq）で、cpu が素直。ctx-switch は OS の仕事だが、部品が見せるのは CPU のレジスタ（PC・SP・CR3）とメモリの値の入れ替わりで、cpu-mode と同じく「OS の下で CPU に何が起きるか」の層にした。os にすると使う所の 09 s5（os）からの印が「同じ層」になる。cpu なら 07 s3（io）と 09（os）の両方から「下」。
2. **ctx-switch の 2 つのタスク。** 第9章 場面5 の図で取り分による交代に見えるのはレンダラ メイン → 合成スレッド（同じ PID 4188）だけで、CR3 が替わらない。09 s5.3 の「別プロセスなら CR3 も」を見せるため、既定は B = ネットワーク（PID 4133、vruntime 118.2 で最小）にし、comp で合成スレッドにした。ネットワークは図ではほとんど待ち（S）なので、既定では「起こされてランキューにいた」と置いた（ランキューの札に「実行可能」と出す）。comp ではネットワークを待ち（S）にした（図の最初の交代の時刻の姿）。
3. **ベクタの番号。** キーボードの 33 は第7章の例（PIC の IRQ0 を 32 番に置く並び）のまま使い、図に「キーボード（第7章の例）」と書いた。Linux ではキーボードの番号は決まっていない（上の vector.c）。タイマは第7章の表の 32 ではなく Linux の 236（0xEC）にした。第9章（Linux の話）の上の場所から開くため。第7章の表との差は「章で直したほうがよい所」に書いた。
4. **EOI の順。** key は第7章の図の順（キーコード → キュー → EOI）、timer は Linux の順（EOI が先）にした。Linux はエッジの割り込みでも EOI を先に書く（`handle_edge_irq`）が、key は第7章の例なので図の順を変えなかった。段階4 の本文から「最後に」を外し、順に頼らない書き方にした。
5. **キーコードの値を出さない。** 第7章 場面3 の図は「キーコード 0x04」と書くが、0x04 は USB HID の A の値（第7章 場面5）で、PS/2 のデータポートから読むのはスキャンコード。部品には値を出さず、章の側の点として書いた。
6. **syscall との違いの見せ方。** 図の下に比べる表（4 列）を置き、段階ごとにその列を x にした。本文は表と同じことを言い直さず、理由だけを書いた（スタックに積むので入れ子でも上書きされない、IDT は番号ごとに 256 行）。
7. **IF = 0 の言い切り。** 「次の割り込みを受け付けない」は NMI と例外を含んでしまうので、「マスクできる割り込みは待たされる」にした（SDM 6.8.1）。
8. **ctx-switch の注記。** 「task_struct には thread.sp だけ」は FPU や fs・gs のベースを落とすので、「thread.sp を置く。FPU と fs・gs のベースは task_struct 側に残す」にした。

Intel SDM:

- INT n の Operation（felixcloutier.com の写し）: 外部割り込み・NMI・例外にも当てはまる。IA-32e では `(vector_number « 4) + 15` が IDT の範囲にあるかを見て 16 バイトの門を読み、新しい RSP を TSS（IST が 0 なら新しい DPL の RSP）から読んで 16 バイトにそろえ、旧 SS:RSP・RFLAGS・CS:RIP（・エラーコード）を積み、その後に `CPL := new code-segment DPL`。割り込みゲートなら IF := 0、TF・NT・RF・VM := 0。
- Vol. 3A 4.6.1（xem.github.io の …-133.html）: 「Some operations implicitly access system data structures … supervisor-mode accesses regardless of CPL」。例は GDT・LDT、割り込みを届けるときの IDT、タスク切り替えか CPL を変えるときの TSS。積む先のスタックは例に無い（直した所 2 の推論）。

計算し直したもの: 33 × 16 = 528 = 0x210、236 × 16 = 3,776 = 0xEC0、0xEC = 236。積む番地 0xDF〜0xDC（SP = 0xDC）、汎用 0xDB、iretq は 0xDC から 0xDF へ読む。iretq は 2 バイトで 0xB6 → 0xB8、0xC0 → 0xC2。ctx-switch の A は 0xD9〜0xDF・thread.sp = 0xD9、B は thread.sp = 0xC9 → 6 個で 0xCA → 戻り番地で 0xCB → 汎用で 0xCC → iretq で 0xCC〜0xCF を読み SP ← 0x5C。vruntime は nice 0 で 120.0 + 3 = 123.0。上の章の値（第7章 場面3 の i7 = mul・i8 = store・IRQ1・33・約 1 µs、第9章 場面5 の PID 4188・4133、vruntime 120.0・121.5・118.2、3 ms、1 回数 µs）と食い違いは無い。

### 直さなかったが気になる点

- 部品の中の印の向き: irq-entry の「ローカル APIC → 第7章 場面3 段階3」（層 io）と ctx-switch の「CR3 → 第9章 場面4 段階2」（層 os）は、部品の層 cpu から見て上の層を指す。第7章 場面3 段階4 から開いた読者には、同じ場面の 1 つ前の段階へ戻る印になる。割り込みコントローラの中を説明する下の層が教材に無いので残した（第9章 場面5 から開いた読者には役に立つ）。CR3 は印の張り替えの表どおり部品 mmu-walk 段階2 へ張り替えれば解消する。
- キーボードの EOI の順: key は第7章の図の順（読む → キュー → EOI）、timer は Linux の順（EOI が先）。Linux は IO-APIC のエッジの割り込み（IRQ1）でも `handle_edge_irq` が先に EOI を書くので、key の順は Linux の順ではない。第7章の例として残した。
- ハンドラの中の PC: 段階4 では PC にコードのまとまりの先頭の番地（0xB0・0xB2・0xB4）を出す。「次の命令の番地」の厳密な値ではない（「ハンドラの行はコードのまとまり」の模式）。
- Linux のハンドラは CPU ごとの IRQ スタックで走る（idtentry.h の `run_sysvec_on_irqstack_cond`・`run_irq_on_irqstack_cond`）。図はタスクのカーネルのスタックだけを描く。
- ctx-switch の既定 net は、第9章 場面5 の図の時刻 3 ms の交代（レンダラ メイン → 合成スレッド、comp）と違う。CR3 を替える姿が第9章 場面5 段階3・場面4 段階2 に要るので、作った担当の判断のまま既定にし、段階3 の本文で前提を明示した。

### 章で直したほうがよい所（作った担当の 4 点への意見）

1. **第9章 場面5 段階3（本文と図の ①〜④）: 直す。** 指摘は Linux 7.4-rc3 のソースと合う（`context_switch` は `switch_mm_irqs_off` が `switch_to` より先、ユーザーのレジスタは入口でカーネルのスタックの pt_regs、task_struct に置くのは thread.sp）。本文の案（155 字）:「走っていたタスクのレジスタ（命令ポインタ＝第6章の PC・汎用レジスタ）は、入口でカーネルのスタックに積まれている。別プロセスなら先に CR3 を切り替え、スタックポインタを task_struct に置いて次のタスクの分を読み込む。直接の費用は 1 回数 µs。TLB やキャッシュが冷える間接の費用も付く。」。図の案: ①「別のプロセスなら CR3 を書き換える」②「スタックポインタを task_struct へ保存」③「次のタスクの task_struct からスタックポインタを読む」④「そのスタックから戻り、積んであった rip から続く」。張り替えの表の 09 s5.3（st.gsw → ctx-switch 段階5）のつなぎの一文は、この直し方と合う。
2. **第7章 場面3 のベクタ表（32 タイマ・33 キーボード・34 NIC）: 直す。** 段階6 の「タイマは 250〜1,000 回/秒（第9章）」は Linux のローカル APIC のタイマで、番号は 236（0xEC）。32 は PIC の IRQ0 を 32 番に置く並びで、Linux の ISA の IRQ0 は起動時 0x30。案: 行を「33 キーボード → kbd_isr」「34 NIC → nic_isr」「236 タイマ（ローカル APIC）」の順にし、題を「ベクタ表（IDT、256 行。33・34 は例）」にする。光らせる行の添え字（`st.idt.rows[2]`）は 1 になる。
