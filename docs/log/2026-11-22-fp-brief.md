## 1. この部は何か

- 教材「YouTubeが見えるまで」の新しい **第X部「関数型」**（第37〜43章の 7 章）。持ち主の依頼は 2 つ。「関数型はコンピューターの何に立ち向かうもの？カリーハワードやモナドや静的型付けなどは何？」と、その答えを受けた「他にも関数型で重要な概念はある？それらのページを作って」。
- 部の問い: **関数型は、計算機の何に立ち向かうのか。** 答えは「書き換えできる状態と、その書き換えの順序（時間）」。第6章の CPU は、レジスタとメモリを命令ごとに書き換える状態機械で、命令型の言語はそれを変数・代入・逐次実行として言語にしている。関数型は、計算のモデルを式の簡約（ラムダ計算）に置く。機械は状態機械のままで、その差はコンパイラとランタイム（クロージャ・ごみ集め・末尾呼び出し）が埋める。
- 各章は、関数型の重要な概念を 1 つずつ扱う。どの章も「その概念は何か」「何と引き換えに何を得るか」「機械（第6章の CPU と第26章のメモリ）の上では何になるか」の 3 つを見せ、章の最後の場面で部の問いへの自分の章の分の答えを言い切る。
- 第VII部「横断」（第26章 型とメモリ、第28章 コンパイラ、第29章 型で意味を表す）を土台にする。静的な型そのもの（静的と動的、型検査、直積と直和、newtype）はそこで済んでいるので、言い直さずにリンクする。
- 関数型の概念の詳しい説明の置き場は、この部（2026-11-22 の持ち主の判断。層の登録簿にも「関数型」の層を足す）。ほかの章が同じ概念に軽く触れている所（第28章 s2.4 の型推論、第30章 s5.2 の閉包、第36章 s4.6 のスコープなど）に説明を任せず、この部の章が詳細を持つ。そこからこの部へのリンクは、調整役が後で足す。
- この部は実在のプログラムを読む部ではない（第VIII・IX部とは違う）。概念を、小さな式と、手元で動かして確かめた出力で見せる（第26〜29章と同じ流儀）。

  1. **状態か、式か** — 第36章の評価器は環境を書き換えながら木を歩いた、を受ける。第6章 場面4 は PC・A・10 番地（sum）・11 番地（n）を 22 命令で書き換えて 6 を得た。文の意味は「前の状態から後の状態へ」で、同じ `sum ← sum + n` でも実行する時点で結果が違う。同じ計算を式 `sumTo 3` の置き換えの列（§4）で行うと、書き換わる場所が無い。式の値はいつ計算しても同じで、等しい式で置き換えられる（参照透過性）。Backus の 1977 年のチューリング賞講演（意味が状態遷移に密着している、という批判）を出典に、部の問いを立てる。機械は変わらず、式の簡約も最後は第6章の機械が実行する、と断る。図の案: 左に状態の表（PC・A・sum・n が命令ごとに変わる）、右に式の列。
  2. **3 つの形** — 項は変数 `x`、抽象 `λx. M`、適用 `M N` の 3 つだけ。括弧の規約（適用は左に結合、λ の本体は右いっぱいまで）。束縛変数と自由変数。束縛変数の名前の付け替え（α変換。`λx. x` と `λy. y` は同じ）。項は木（第28章 s1.4）。図の案: 項の木と、変数から束縛する λ への線。
  3. **β簡約** — `(λx. M) N` を、M の中の x を N に置き換えた項にする。簡約できる形を簡約基と呼ぶ。数と ＋ を足した例 `(λx. x + 1) 2` → `2 + 1` → `3`（数と算術は λ計算の外から足した、と断る）。変数の捕獲: `(λx. λy. x) y` を素直に置き換えると `λy. y` になり意味が変わるので、先に α変換して `λz. y`。図の案: 引数が x の位置へ流れ込む動き。
  4. **順序と合流性** — 1 つの項に簡約基が 2 つある `(λx. x + x) ((λy. y + 1) 2)`。内側から進めると `(λx. x + x) 3` → `3 + 3` → 6。外側から進めると引数が 2 か所に写り、`(λy. y + 1) 2` を 2 回計算して 6。どの順でも、行き着く正規形は 1 つ（Church–Rosser の定理、1936 年）。止まらない項 `Ω = (λx. x x) (λx. x x)` と、`(λx. 3) Ω`: 外側からなら 1 歩で 3、内側からは止まらない。最左最外の順（正規順序）は、正規形があれば必ず着く。命令型では順序が意味の一部だが、ここでは止まる限り順序は結果を変えない。評価の順序の続きは第40章。図の案: 2 つの道がひし形に分かれて 6 で合う。
  5. **数もデータも関数** — 3 つの形だけで真偽・数・対が書ける（Church の符号化）。`true = λt. λf. t`、`false = λt. λf. f`、分岐は適用。数 n は「f を n 回当てる」関数で `3 = λf. λx. f (f (f x))`。足し算 `plus = λm. λn. λf. λx. m f (n f x)` で 2 ＋ 1 を簡約して 3 の形になるまでを追う（列は小さな簡約器で確かめる）。実際の言語は数や構造体を機械の表現で持つ（第26章）。図の案: f の重なりの数で数を見せる。
  6. **再帰と、計算できること** — λ には名前が無いので、自分を呼ぶには不動点コンビネータ `Y = λf. (λx. f (x x)) (λx. f (x x))`（`Y g` と `g (Y g)` は同じ項 `g W` に簡約されるので等しい。`Y g` が `g (Y g)` そのものに簡約されるのではない。そう簡約されるのは Turing の Θ）を使う。sumTo を Y で書く。λ計算で定義できる関数と、チューリング機械で計算できる関数は同じ（Church 1936、Turing 1936〜37）。実際の関数型言語は「λ計算 ＋ 型 ＋ データ ＋ 速い実装」。Haskell の記法との対応を 1 度示す。章の答えと、第X部の道（第38〜43章が何を足すか）。
- 用語: ラムダ計算／抽象と適用／束縛変数と自由変数／α変換／β簡約／簡約基／正規形／合流性（Church–Rosser）／Church の符号化／不動点コンビネータ／参照透過性。
- 注意: 「関数型言語には状態が無い」と書かない（式の意味に状態が入らない、と書く。処理系は機械の状態を使う）。適用順序と値呼びは同じではない（値呼びは λ の中を簡約しない）ので、「内側から」「外側から」と正規順序・適用順序の語を取り違えない。λ計算の発表の年（Church の 1930 年代の論文）、Church–Rosser、Turing の等価性の証明、Backus の講演は、文献を確かめて年を書く。「参照透過性」の語の出どころ（Quine、Strachey）は確かめられた範囲で。

### 第38章 高階関数とクロージャ（38-closure.html）

- meta: eyebrow `第X部 関数型 ／ 第38章`、title `高階関数とクロージャ`、prev 第37章「ラムダ計算」、next 第39章「不変データ」（39-immutable.html）。
- 役目: 関数を数と同じ値として扱う、を実際の言語と機械の上で見せる。場面2（クロージャの中身）と場面6（末尾呼び出しが機械語のループになる）は、実物の出力で見せる。
- 関係する章: 第36章 s4.2・s4.6（saba の関数は呼び出した側の環境をたどる。字句的スコープとの違い）、第30章 s5.2（閉包と Box<dyn Fn>）、第27章 s5.5、第6章 s4、第28章 s4.2、第29章 s2。
- 6 場面:
  1. **関数は値** — 第37章では関数しか無かった、を受ける。値としてできること 3 つ（引数に渡す、戻り値にする、変数やデータ構造にしまう）。関数を受け取るか返す関数が高階関数。`map (*2) [3,2,1]` ＝ `[6,4,2]`。同じことの JavaScript（`[3,2,1].map(x => x * 2)`）と Rust。C の関数ポインタは渡せるが、実行中に新しい関数を作れない（環境が無い）。「第一級」の語の出どころ（Strachey、1967 年の講義）は確かめて書く。Haskell の記法の初出（§5）。
  2. **クロージャ ＝ コード ＋ 環境** — `addN n = \x -> x + n`、`add3 = addN 3`、`add3 2` ＝ 5。本体 `x + n` の n は自由変数で、addN の呼び出しが終わった後も要る。スタックの枠は呼び出しが終わると消える（第27章 s5.5）ので、n をスタックには置けない。関数の値は「コードの番地」と「自由変数の値を入れた環境」の組になる（クロージャ。Landin が 1964 年に名付けた、は確かめて書く）。実物: Rust のクロージャは捕まえた変数を欄に持つ無名の構造体（§4 の 4・0・16 バイト。16 は中身への番地と、コードの番地の表への番地）。JavaScript（V8）は関数の物が環境（Context）を指す。字句的スコープ（定義した場所の環境を持つ）と、第36章 s4.6 の saba（呼び出した側の環境をたどる）の違いを、同じ例で答えが変わる所で見せる。図の案: スタックの枠が消え、ヒープに環境が残る。
  3. **カリー化と部分適用** — 2 引数の関数を「1 つ受け取り、残りを受け取る関数を返す関数」として表す（カリー化）。`add :: Int -> Int -> Int` は `Int -> (Int -> Int)`。引数を一部だけ渡すのが部分適用で、`add 3` は場面2 のクロージャ。`map (add 3) [3,2,1]` ＝ `[6,5,4]`。カリー化（形の変換）と部分適用（引数を一部渡すこと）は別の語。処理系は毎回クロージャを作るわけではない（GHC は引数が揃った呼び出しを直接の呼び出しにする。Core か機械語で確かめられた範囲で書く）。名前の由来（Schönfinkel 1924、Curry）は確かめて書く。
  4. **合成** — `(f . g) x = f (g x)`。§4 のパイプラインを 3 つの部品に分けて値を流す（`[3,2,1]` → `[3,1]` → `[6,2]` → 8）。前の出力の型と次の入力の型が合えばつながる。途中に名前の付いた変数（状態）が無い。命令型のループは「選ぶ・変える・足す」が 1 つの本体に混ざる。Rust の `iter().filter().map().sum()` は release で 1 つのループになる（機械語で確かめる。第28章 s4.2）。
  5. **再帰と畳み込み** — リストは「空 `[]`」か「先頭と残り `x : xs`」（直和と直積。第29章 s2.1・s2.3）。関数は場合ごとに定義する。`sum [] = 0`、`sum (x:xs) = x + sum xs`。同じ形の再帰を 1 つの高階関数にしたのが `foldr`。`foldr (+) 0 [3,2,1]` は `:` を `+` に、`[]` を 0 に置き換えた `3 + (2 + (1 + 0))`。map も filter も foldr で書ける。データの形に沿った再帰は、有限のリストなら必ず止まる。図の案: リストの `:` が `+` に入れ替わる。
  6. **末尾呼び出し** — `sumTo 3` は呼び出しの枠を 4 枚積む（sumTo 3・2・1・0）。深い再帰はスタックを使い切る（Node.js の実測。§4）。関数が最後にすることが呼び出しだけなら（末尾呼び出し）、いまの枠を使い回せる。累積引数の形 `go acc n = if n == 0 then acc else go (acc + n) (n - 1)` は、機械語では call ではなく、先頭へ戻る飛び越しになる（gcc 15.2 の -O2、rustc -O、GHC -O2 の出力を見て、確かめた形を書く。gcc は末尾でない sumTo もループにすることがあるので、-O0 と -O2 を比べるなど、見たものを正確に書く）。これは第6章 場面4 の JNZ で戻るループと同じ形で、acc と n が sum と n の役をする。保証は言語ごとに違う（Scheme は仕様が求める。ECMAScript 2015 は仕様に入ったが実装したエンジンは限られる。Rust と C は最適化しだい。どれも確かめて書く）。章の答え。
- 用語: 第一級関数／高階関数／クロージャ／環境／字句的スコープ／カリー化／部分適用／関数合成／畳み込み（fold）／末尾呼び出し／累積引数。
- 注意: 最適化の有無を「保証」と書かない。Rust のクロージャの大きさは捕まえ方（move か参照か）で変わる（参照で捕まえると 8 バイト。確かめる）。

### 第39章 不変データ（39-immutable.html）

- meta: eyebrow `第X部 関数型 ／ 第39章`、title `不変データ`、prev 第38章「高階関数とクロージャ」、next 第40章「遅延評価」（40-lazy.html）。
- 役目: 値を書き換えないと決めたとき、更新をどう表し、何を払い、何を得るか。データ構造の章（第27章）の続きとして読める形にする。
- 関係する章: 第27章 s1.3・s1.4・s4（木）・s4.2（ビットの木）、第26章 s6.3・s6.5、第28章 s3.4（SSA）・s4.4（別名が無いという事実）、第33章 s2（Rc）、第9章 s2（スレッド）。
- 6 場面:
  1. **別名と書き換え** — 関数を値にした次は、データも変えない値にする、と受ける。2 つの名前が同じ物を指すとき（別名）、片方からの書き換えがもう片方から見える（§4 の JavaScript の sort）。渡した配列を関数が書き換えるかどうかは、呼び出しの式からは分からない。書き換えを無くすと、別名があっても違いを観測できず、共有が安全になる。Rust は別の答え（共有するか、書き換えるかのどちらか。第26章 s6.5、第28章 s4.4）。コンパイラの中間表現も値を 1 回だけ決める形を使う（第28章 s3.4 SSA）。
  2. **リストは先頭に足す** — `xs = [3,2,1]` は 3 個のセル（第27章 s1.3 の連結リスト）。`ys = 0 : xs` は新しいセルを 1 個作り、残りは xs と共有する。xs は変わらず、両方の版が使える（永続データ構造。記憶装置に残す意味の「永続化」とは別、と 1 句添える）。先頭に足すのは O(1)、末尾に足す・途中を変えるのは、そこまでのセルを作り直すので O(n)。図の案: 2 つの名前が同じ尾を指す。
  3. **木は経路だけを写す** — 二分探索木（7 節）に 1 つ足す。根から足す場所までの経路の節だけを新しく作り、ほかの部分木は古い版と共有する。新しく作る節は深さの分だけ（O(log n)）。根が 2 つ（古い版と新しい版）残る。Haskell の `data Tree` と `insert`。出典（Driscoll・Sarnak・Sleator・Tarjan の「Making data structures persistent」、Okasaki の『Purely Functional Data Structures』）は確かめて書く。図の案: 新しい節だけ x、共有する部分木は無彩色。
  4. **幅の広い木（HAMT と永続ベクタ）** — 配列の「i 番目を書き換える」を不変でやる。添字を 5 ビットずつに切り、1 節 32 本の枝の木をたどる（第27章 s4.2 と同じ道具）。32⁴ ＝ 1,048,576 なので、約 100 万要素でも深さ 4。更新は経路の節（各 32 欄）だけを写す。具体的な添字を 1 つ決めて 5 ビットずつの切り方を追う（計算して確かめる）。出典と実装（Bagwell の HAMT、Clojure の永続ベクタ、Scala、Immutable.js）は確かめて書く。配列より遅い理由（番地をたどる回数。第27章 s1.4）も書く。
  5. **ごみ集め** — 共有すると、あるセルを最後に使うのが誰かを書き手が決められない（第26章 s6.3 の解放後の使用は、これを人が間違えた例）。届かなくなった物を処理系が見つけて回収する（ごみ集め。Lisp が最初、McCarthy の 1960 年の論文、は確かめて書く）。世代別のごみ集め: 多くの物はすぐ使われなくなるので、新しい領域を頻繁に集める。割り当ては番地を進めるだけ。GHC の `+RTS -s` で、割り当てた総バイト数と、生き残った最大の量を実測して比べる（短命の物が多いことが数で見える。小さなプログラムで）。参照の数を数える方法（第33章 s2 の Rc）との違いを 1 段階で。
  6. **得るもの** — (1) 複数のスレッドが同じ値を読める。書き換えが無ければデータ競合が起きない（第9章 s2）。(2) 古い版が残るので、元に戻す・比べるが安くできる。Git は内容のハッシュで名付けた不変の物（blob・tree・commit）の木で、1 ファイルを変えると、そのファイルから根までの経路の物だけが新しくなる（一時置き場に小さなリポジトリを作り、`git count-objects` などで数を確かめる）。(3) 変わったかどうかを参照の比較 1 回で判定できる。代償は場面4・5。章の答え（「いつ読むか」が意味から消える）。
- 用語: 不変（イミュータブル）／別名／永続データ構造／構造共有／cons セル／経路コピー／HAMT／ごみ集め（GC）／世代別 GC／データ競合。
- 注意: 「永続」の 2 つの意味を混ぜない。O 記法は何の操作かを書く。GHC のごみ集めの既定値（領域の大きさなど）は、GHC 9.6 の利用者の手引きか `+RTS --info` で確かめた値だけ書く。遅延評価の処理系はサンクを上書きするので「古い物は新しい物を指さない」と言い切らない（第40章の話）。

### 第40章 遅延評価（40-lazy.html）

- meta: eyebrow `第X部 関数型 ／ 第40章`、title `遅延評価`、prev 第39章「不変データ」、next 第41章「型推論と多相」（41-inference.html）。
- 役目: 引数をいつ計算するか、という規則（評価戦略）と、Haskell の遅延評価の中身（サンク）、得るもの（無限のデータ、部品の分離）、代償（スペースリーク）。
- 関係する章: 第37章 s4（順序と合流性。この章の出発点）、第38章 s2（クロージャ。サンクは同じ形）・s4・s6、第39章 s5。
- 6 場面:
  1. **引数はいつ計算するか** — 第37章 場面4 の 2 つの順序を、言語の規則として見る。値呼び（引数を先に計算する。C・Rust・JavaScript など多くの言語）、名前呼び（式のまま渡し、使うたびに計算する。Algol 60）、必要呼び（式のまま渡し、最初に使ったときに計算して結果を覚える。Haskell の処理系）。`f x = x + x` に `f (1 + 2)` を渡すと、足し算 `1 + 2` の回数は 1・2・1 回。引数を使わない `g x = 3` に止まらない式や `undefined` を渡すと、値呼びは止まらず（または落ち）、ほかは 3（ghci の `let f x = 3 in f undefined` は 3）。純粋な式なら、止まる限り結果は同じ（合流性）で、違うのは手間と止まるかどうか。
  2. **サンク** — 計算していない式は、ヒープの上の物（サンク）として置く。中身は「計算するコードの番地」と「自由変数の値」で、第38章 場面2 のクロージャと同じ形。値が初めて要るときにコードを走らせ、サンクを結果で上書きする。2 回め以降は値を読むだけ。関数型の処理系の内側で書き換えが起きているが、式の値は変わらない（表し方が「これから計算する」から「計算済み」に変わるだけ）ので、プログラムからは観測できない。§4 の `:sprint` の 3 つの出力を、そのまま図に出す。
  3. **どこまで計算するか** — 値を要るのは、場合分け（パターンマッチ）、組み込みの演算、最後は main の入出力。評価は、いちばん外の構築子が見える所（弱頭部正規形）で止まる。`length` はセルの骨組みだけを評価し、要素は評価しない（`[_,_,_]`）。`seq` と `foldl'` は強制する道具。「遅延評価」（処理系の方法）と「非正格」（言語の意味）の語の違いを 1 段階で。
  4. **無限のデータ** — `[1..]` は終わりの無いリスト。`take 3 [1..]` は `[1,2,3]`。使う側が要る分だけ、作る側が動く。§4 の `takeWhile (< 40) (map (^2) [1..])` を、要求が後ろから前へ伝わる動きで追う。「作る」と「選ぶ」と「止める」を別々の部品として書ける（Hughes の「Why Functional Programming Matters」の主張。年を確かめて書く）。値呼びの言語では、自分で定義した `if` は両方の枝を計算してしまう。`&&` と `||` の短絡は、値呼びの言語にある遅延の例。
  5. **代償（スペースリーク）** — `foldl (+) 0 [1..n]` は、足し算をせずにサンクの鎖 `((0 + 1) + 2) + …` を n 個積む。`foldl'` は 1 歩ごとに強制するので、積まない。n ＝ 100 万で、GHC 9.6.7 の `-O0` と `-O2`、foldl と foldl' の 4 通りの `+RTS -s`（最大の常駐量）を実測して表にする（-O2 では正格性解析が foldl も直すことがある。測った結果を書く。第40章の担当の実測では、-O2 は `-fno-strictness` でも直り、正格性解析が効いたと言えるのは -O1 だけだった。`sum` は base の版によって foldl' で定義されているので、例には foldl を明示して使う）。式の形から時間とメモリを読みにくいこと、遅延評価と副作用の相性が悪く、それが Haskell を純粋に保ったこと（「A History of Haskell」の記述を確かめて引く）。
  6. **正格な言語の中の遅延** — Rust の Iterator は、`map` だけでは何も計算せず、`sum` や `collect` が引くと動く（使わなかったときの rustc の警告文を実物で）。JavaScript のジェネレータと Iterator のヘルパー（§4）。既定で遅延（Haskell）と、既定は正格で必要な所だけ遅延（多くの言語）という設計の分かれ方。「計算の記述」と「実行」を分ける考えは第42章の IO に続く。章の答え。
- 用語: 評価戦略／値呼び／名前呼び／必要呼び／サンク／強制／弱頭部正規形（WHNF）／非正格／無限リスト／スペースリーク／正格性解析。
- 注意: `:sprint` は型を `[Int]` と書いた束縛で見る（多相のままだと共有されず、いつまでも `_`）。実測は n ＝ 100 万までにする（1,000 万は数百 MB を使う）。Algol 60 の名前呼び、必要呼びの出典は確かめて書く。

### 第41章 型推論と多相（41-inference.html）

- meta: eyebrow `第X部 関数型 ／ 第41章`、title `型推論と多相`、prev 第40章「遅延評価」、next 第42章「モナド」（42-monad.html）。
- 役目: 静的な型のうち、関数型の言語で育った 3 つ（型推論、パラメトリック多相、型クラス）。静的な型そのものの説明（第26章 s4、第28章 s2、第29章）は繰り返さず、リンクする。
- 関係する章: 第28章 s2.2・s2.4（Rust の型推論は関数の中だけ）・s3.6（単相化）、第26章 s3.6・s4、第29章 s2、第30章 s3・s5.2、第37章 s4（Ω）。
- 6 場面:
  1. **型は方程式で決まる** — ここまでの章は型を書かずに来た、と受ける。`twice f x = f (f x)` の型を、注釈なしで決める。分からない型に変数を置き（f に α、x に β、結果に γ）、使われ方から等式を集める（f を x に当てるので α ＝ β → δ、f をその結果に当てるので α ＝ δ → γ）。Rust は関数の引数と戻り値の型を書かせ、本体の中だけ推す（第28章 s2.4）。ML や Haskell は関数の境目も推す。図の案: 式の木の節に型変数を付け、等式が集まる。
  2. **単一化** — 集めた等式を解く。α ＝ β → δ と α ＝ δ → γ から β ＝ δ、δ ＝ γ。全部が同じ型になり、`twice :: (t -> t) -> t -> t`（§4。ghci の表示のまま）。両辺が同じ形になるように型変数へ型を代入する操作が単一化（Robinson の 1965 年の論文、は確かめて書く）。失敗は 2 通り: 形が合わない（§4 の `'a' && True`）、型変数が自分を含む型と等しくなる（§4 の `\x -> x x`。出現検査）。だから第37章 場面4 の Ω は、この型の体系では書けない。型の付く項は必ず止まる、という単純型付きラムダ計算の性質は、確かめられた範囲で書く。
  3. **let 多相と主要型** — `id x = x` の型は「どの型 a についても a → a」。使う場所ごとに a を別の型にできる（`(id 'a', id True)`）。定義（let）に付いた型は一般化されるが、λ の引数は一般化されない（§4 の `\f -> (f 'a', f True)` は型が付かない）。推論の結果は最も一般的な型（主要型）で、ほかの型はその具体化。出典（Hindley 1969、Milner 1978、Damas と Milner 1982）は確かめて書く。注釈が要るようになる拡張があること（高階ランクの多相など）を 1 句。
  4. **型が振る舞いを縛る（パラメトリシティ）** — `f :: a -> a` の関数は、a が何の型かを知らないので、値を調べることも作ることもできない。返せるのは受け取った値だけで、止まる関数なら `id` しかない。`g :: [a] -> [a]` は要素を並べ替え、捨て、写せるが、要素を作れず、中身で分岐できない。そこから `map h (g xs)` ＝ `g (map h xs)` が型だけで決まる（Wadler の「Theorems for free!」。年を確かめる。具体的な g と h で両辺を計算して見せる）。機械の側: 多相な関数は、値を番地で一様に表して 1 つのコードで済ますか、型ごとにコードを写す（単相化。第28章 s3.6）。型による分岐を許す言語の機能（実行時の型の検査など）があると、この性質は弱まる、と条件を書く。
  5. **型クラスと辞書渡し** — `+` は Int にも Double にも使えるが、型ごとに別の実装（アドホック多相）。`Num a => a -> a -> a` の `Num a =>` は「a に足し算などの実装があること」という条件（型クラス。Wadler と Blott の 1989 年の論文、は確かめて書く）。コンパイラは条件を、実装の表（辞書）という隠れた引数に変える。`sumAll :: Num a => [a] -> a` を `ghc -O0 -ddump-simpl`（`-dsuppress-all` などで読みやすく）で出し、辞書の引数（`$dNum`）が実際に出ることを見せる。-O2 で型が決まる呼び出しが特殊化されるかも見て、見たとおりに書く。Rust のトレイトは同じ考えで、総称は単相化（型ごとの機械語）、`dyn Trait` は実装の表への番地を値と一緒に持つ（§4 の `Box<dyn Fn(i32) -> i32>` の 16 バイト。第38章 場面2。第30章 s5.2 に 16 バイトの記述は無い）。
  6. **型を作る型と Functor** — `Maybe`・`[]`・`IO` は、型を受け取って型を作る（種は `* -> *`。§4）。リストの map、Maybe の map を 1 つの名前にまとめたのが `fmap :: Functor f => (a -> b) -> f a -> f b` で、f は型を作る型（高カインドの多相）。則 `fmap id = id` と `fmap (g . h) = fmap g . fmap h` は、コンパイラが確かめない約束。Rust には f に当たる書き方が（2026 年時点の安定版では）無く、`Option::map`・`Iterator::map`・`Result::map` は別々のメソッド（第30章 s3。確かめて書く）。次の章のモナドは Functor の先にある。章の答え。
- 用語: 型推論／型変数／単一化／出現検査／let 多相／主要型／パラメトリック多相／パラメトリシティ／アドホック多相／型クラス／辞書渡し／種（カインド）／Functor。
- 注意: エラーの文は GHC 9.6.7 の実物を写す（§4。ファイルに書いたときと ghci で文が違うことがある）。「Hindley–Milner は注釈が一切要らない」は Haskell 全体には当てはまらない（型クラスや拡張で要る所がある）。

### 第42章 モナド（42-monad.html）

- meta: eyebrow `第X部 関数型 ／ 第42章`、title `モナド`、prev 第41章「型推論と多相」、next 第43章「カリー＝ハワード対応」（43-curry-howard.html）。
- 役目: 純粋な関数に書けないこと（失敗、状態、入出力）を、戻り値の型に出し、つなぐ演算を型ごとに決める。第37章で言語から外した「状態」と「順序」が、ここで型に現れる形で戻る。
- 関係する章: 第41章 s5・s6（型クラス、Functor）、第38章 s4（合成）・s6（累積引数）、第37章 s1、第6章 s4、第30章 s3・s6（Option と Result）、第10章 s5（Promise とイベントループ）。
- 6 場面:
  1. **純粋な関数に書けないこと** — Functor の先、と受ける。純粋な関数は、同じ引数に同じ結果を返し、ほかに何もしない。失敗するかもしれない、状態を読み書きする、入出力をする、は「引数から戻り値へ」の外にある（作用、副作用）。JavaScript の `() => ++counter` は、型が `() => number` でも呼ぶたびに違う値を返す。方針: 作用を戻り値の型に出す。失敗するかもしれない Int は `Maybe Int`、状態 s を使う計算は `s -> (a, s)`、入出力をする計算は `IO a`。型を見れば、何をしうるかが分かる。
  2. **失敗をつなぐ（Maybe）** — §4 の `divBy`。3 回つなぐと、「Nothing なら Nothing、Just x なら次へ」という場合分けが段々に深くなる。この繰り返しを 1 つの演算にしたのが `>>=`（`Maybe a -> (a -> Maybe b) -> Maybe b`）。§4 の 2 つの式（`Just 1` と `Nothing`）を、値が流れる動きで追う。途中で Nothing になると、残りの関数は呼ばれない。Rust の `Option::and_then` と `?`（第30章 s3・s6）は同じ形。
  3. **モナド（3 つの部品と 3 つの則）** — 型を作る型 M、`return :: a -> M a`、`(>>=) :: M a -> (a -> M b) -> M b`。則は 3 つ: `return a >>= f` ＝ `f a`、`m >>= return` ＝ `m`、`(m >>= f) >>= g` ＝ `m >>= (\x -> f x >>= g)`。Maybe で 3 つとも具体的な値で確かめて見せる。則の意味: `a -> M b` の形の関数どうしの合成が、普通の関数合成（第38章 s4）と同じく、括弧の付け方によらず、何もしない関数を挟んでも変わらない。`do` は `>>=` の別の書き方（`do { x <- m; f x }` ＝ `m >>= \x -> f x`）。則はコンパイラが確かめない。Functor・Applicative・Monad の包含と、出典（Moggi の「Notions of computation and monads」、Wadler の論文）は確かめて書く。圏論の定義（自己関手と 2 つの自然変換）は名前だけ添える。
  4. **状態をつなぐ（State）** — 状態を純粋に扱うには、状態を引数で受け取り、戻り値で返す（`s -> (a, s)`）。§4 の例（0 → 3 → 5 → 6）を、まず手で状態を渡す形で書く（`s1`・`s2`・`s3` と名前が増え、渡し間違えても型は通る）。`newtype State s a = State (s -> (a, s))` の `>>=` が受け渡しを引き受ける。状態は「書き換わる場所」ではなく「関数から関数へ渡る値」で、第6章 場面4 の sum の列と同じ値が式の中を流れる（第38章 s6 の累積引数と同じ考え）。State は自分で定義して動かして確かめる（base には無い。transformers の `Control.Monad.State` を使うなら、手元で import できるか確かめる）。
  5. **入出力（IO）** — `getLine :: IO String` は文字列ではなく、「実行すると文字列が得られる入出力の手順」という値。純粋な式は手順を組み立てるだけで、実行するのはランタイム。入口は `main :: IO ()` の 1 つ。`IO a` から a を純粋に取り出す関数は（安全なものは）無いので、型に IO の無い関数は入出力をしない、と型で分かる。GHC の中身は §4 の newtype で、場面4 の State と同じ形。渡していく「世界」は実行時には大きさ 0 の印で、前の入出力の結果を次が受け取る形にすることで順序を固定する（これは GHC の実装で、Haskell の仕様が決めた形ではない、と断る。`main = getLine >>= putStrLn` の `-ddump-simpl` で `State# RealWorld` が出ることを確かめる）。第37章で消えた「順序」は `>>=` の中に戻っている。出典（Peyton Jones と Wadler の「Imperative functional programming」など）は確かめて書く。
  6. **ほかの形と、ほかの道** — リストもモナド（§4 の `[1,10,2,20]`。答えが複数ある計算）。ほかの言語の同じ形: Rust の `and_then` と `?`、`async`／`.await`、JavaScript の `Promise.prototype.then`（§4。入れ子の Promise を自動で平らにするので、モナド則を厳密には満たさない、と確かめた範囲で書く）。モナドは組み合わせにくい（2 種類の作用を同時に使うには変換子が要る）ので、別の道として代数的エフェクトとハンドラがある（出典と、実装した言語は確かめて書く）。章の答え。
- 用語: 作用（副作用）／純粋な関数／Maybe／`>>=`（bind）／return（pure）／モナド則／do 記法／State／IO／Applicative／代数的エフェクト。
- 注意: 「モナド ＝ 副作用」と書かない（モナドは 3 つの部品と則を持つ構造で、作用の扱いは使い道の 1 つ）。「IO は不純」とも「IO は純粋」とも言い切らず、何が純粋で（手順を組み立てる式）、何が作用を起こすか（ランタイムの実行）を分けて書く。比喩（箱・容器・ブリトー）は使わない。

### 第43章 カリー＝ハワード対応（43-curry-howard.html）

- meta: eyebrow `第X部 関数型 ／ 第43章`、title `カリー＝ハワード対応`、prev 第42章「モナド」。next は置かない（教材の最後の章）。まとめの注記は第36章のまとめに倣う（教材の終わり。目次と第1章へ）。
- 役目: 型検査の規則と論理の証明の規則が同じ形をしている、という対応を見せ、部を閉じる。場面6 で第X部の問いに全体として答える。これは何かに立ち向かう手法ではなく、静的な型が論理であることの観察。
- 関係する章: 第41章 s1〜s3、第37章 s3・s4（β簡約、Ω）、第29章 s2.1・s2.3（直積と直和）・s3.6・s6、第26章 s6.4、第38章 s4、第42章。
- 6 場面:
  1. **2 つの規則が同じ形** — 論理の規則「A → B と A から B」（含意の除去）と、型の規則「f : A → B と x : A から f x : B」（関数の適用）を上下に並べ、項（f、x、f x）を消すと同じになることを見せる。「A を仮定して B を導けば A → B」（含意の導入）は λ抽象の規則。対応の表: 命題 ＝ 型、証明 ＝ プログラム（項）、仮定 ＝ 変数。Curry（1934 年）と Howard（1969 年の原稿、1980 年に出版）の名前と年は確かめて書く。図の案: 2 つの推論規則を重ね、項の部分だけが消える。
  2. **「かつ」「または」「ならば」はデータ型** — A ∧ B は直積 `(A, B)`（両方の証明の組。第29章 s2.1）。A ∨ B は直和 `Either A B`（どちらかの証明と、どちらかの印。第29章 s2.3）。A → B は関数。例: `(A ∧ B) → (B ∧ A)` の証明は `\(a, b) -> (b, a)`。`A → (B → A)` は `\a _ -> a`。`(A → B) → (B → C) → (A → C)` は合成（第38章 s4）。`(A ∨ B) → (A → C) → (B → C) → C` は場合分け。どれも GHC の型検査を通ることを確かめて見せる。「その型の（止まる）項がある」ことが「その命題が証明できる」こと。
  3. **偽と否定、古典論理との差** — 偽は値の無い型 `Void`。偽からは何でも出る（`absurd :: Void -> a`）。否定 ¬A は `A -> Void`。対応する論理は直観主義論理で、排中律 `Either a (a -> Void)` と二重否定の除去 `((a -> Void) -> Void) -> a` に当たる（止まる）項は書けない。書ける例は、二重否定の導入 `a -> ((a -> Void) -> Void)` と対偶 `(a -> b) -> ((b -> Void) -> (a -> Void))`（GHC で確かめる）。証明が「作り方」である（A ∨ B の証明は、どちらが成り立つかを持つ）ことが差の理由。古典論理は制御の演算子（call/cc）に対応する、という結果（Griffin、1990 年）は確かめて 1 句。
  4. **評価は証明の整理** — 証明の中の回り道（ある形を導入してすぐ除去する）を取り除く操作が、β簡約（第37章 s3）と同じ。`fst (a, b)` → `a` は、∧ を導入してすぐ除去する回り道を消す。`(λx. M) N` → M[x:=N] は、→ の回り道を消す。単純型付きラムダ計算の項が必ず止まることは、どの証明も回り道の無い形にできることに当たる。対応の表の 3 行め: 評価 ＝ 証明の正規化。出典（Gentzen、Prawitz など）は確かめられた範囲で。
  5. **「すべて」「ある」と依存型** — 多相 `forall a. a -> a` は、型（命題）についての「すべて」（第41章 s3）。値についての「すべての n について」「ある n が存在して」を言うには、型が値に依存できる必要がある（依存型。Π 型が「すべて」、Σ 型が「ある」）。例: 長さを型に持つ列 `Vec a n` と、長さが n ＋ m になることを型が言う連結。範囲外の添字を型で防ぐ（第26章 s6.4、第29章 s3.6 からの続き）。証明支援系（Rocq（旧 Coq）、Agda、Lean、Idris）と、実際に証明された物（四色定理、コンパイラ CompCert など。seL4 は Isabelle/HOL で、依存型の例ではないので、挙げるなら区別する）。どれも確かめて書く。手元に証明支援系は無いので、コードを出すなら「手元では動かしていない」と書く。
  6. **どこまで信じられるか、と第X部の答え** — Haskell では、`undefined` と止まらない再帰（`loop = loop`）がどの型にも属するので、どの命題も「証明」できてしまい、論理としては矛盾する（プログラミング言語としては困らない）。証明支援系は、関数が必ず止まり、場合分けが漏れないことを検査する。その代わり、止まらないかもしれない計算は直接には書けない。型検査が証明するのは、型として書いた性質だけ（第29章 s6）。最後に第X部の答え: 関数型が立ち向かう相手は、書き換えできる状態と書き換えの順序。道具は、式の簡約（第37章）、値としての関数（第38章）、変えないデータ（第39章）、順序を処理系に預ける評価（第40章）、振る舞いを縛る型（第41章）、作用と順序を型に戻すモナド（第42章）、型は命題という対応（第43章）。機械は第6章の状態機械のままで、差はコンパイラとランタイムが埋める。各章の場面へリンクする。
- 用語: カリー＝ハワード対応／命題／証明／自然演繹／含意／連言と直積／選言と直和／空の型（Void）／直観主義論理／証明の正規化／依存型／証明支援系／全域性。
- 注意: 「書けない」こと（排中律の項が無い）は、コンパイルして示せない。定理として述べ、根拠を確かめて書く。論理記号（∧ ∨ → ¬ ∀ ∃）は初出で読みを 1 回添える。Rocq への改名（2025 年）は確かめて書く。
