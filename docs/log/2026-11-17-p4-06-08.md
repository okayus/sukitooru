### 判断

- 場面1・3 の板（`YT.zoom`）と同じ行き先の印（A → 05 s3.1、ALU → 04 s6.3、制御装置 → 04 s3.6、PC + 1 → 04 s5.2）は、読者が自分で開ける入口として張った。板は段階に入って 1〜2.4 秒後に開き、開いている間は札が隠れる。説明欄の下の一覧からはいつでも開ける。止めているときは板が最初から開くので、札は出ず一覧だけになる。札は板の閉じている時間（段階の最初と、場面3 段階5 の板の切り替えの間）に見える位置に置いた。
- 板が開く前、元の箱の周りに合図の枠（脈打つ枠）が出るので、札はその線の外に置いた。
- 同じ層の印 5 つ（s2.1 → s3.3、s2.3 → s3.2、s4.2 → s3.1、s4.3 JNZ → s3.3、s4.5 Z → s1.3）は、行き先の場面の板が一段下の回路（解読の AND と NOT、PC + 1 の半加算器、ゼロ検出の OR と NOT）を見せるので、第4章の場面へ直接張るより先にした。s2.1・s2.3・s4.2 は例の値も上と同じ。
- メモリは「例が違う」にした。YT-8 の図は 1 番地を 8 ビットの 1 行に縮めた模式で、05 s5.5 の DRAM は 1 行が数千セル・列アドレスで選ぶ。05 s3.4（レジスタファイルのデコーダ）も候補だったが、図に DRAM と書いてあるので DRAM の配列にした。
- s2.4 の第26章 場面1 へのリンク（数の読み方は読む側が決める）は、型の層が CPU の上なので印にしなかった。

### 判断

- 「横」2 本はどちらも正しい依存。s1.3 の PCIe の差動線 → 13 s1.2 は、差動信号の説明が第13章にしか無く、登録簿の io の down に phy が無い。s4.2 のリング → 27 s5.2 は、リングバッファの説明が第27章にしか無く（27 s5.2 自身が第7章 場面4 の輪を例に挙げる）、algo は io の下に無い。
- 割り込みの入口（s3.4・s3.5）は、部品 cpu-mode の syscall（段階3）・sysret（段階5）に張って「例が違う」にした。部品の段階5 の本文が「M を 0 にするのは、syscall・割り込み・例外など、決まった入口へ飛ぶ仕組みだけ」と書くので、モードが切り替わる仕組みは同じ。命令の切れ目で INT を見る所・IDT を引く所・スタックに積む所は部品にも無いので、別の行で「無い」にした。layers-plan §1 が挙げた「第7章 場面3 段階4 も同じ抽象で止まる」の穴は、モードの所が部品で埋まり、入口の所が残る。
- s2.5 の保護は、本文の「カーネルモードの OS だけ」に合わせて部品 cpu-mode 段階4（モードとページの印の照らし合わせ）に張った。図の注記「ページテーブルに無い」は表に載っていない場合で、部品に無いので「例が違う」にした。
- s2.2 の MMIO の行き先の選び方は、05 s3.4 の「番号 4〜5 ビットをデコーダが 1 本の選択線に変える。これは次の場面のメモリの選び方と同じ」に張った。実物は範囲で比べるので「例が違う」。

### 判断

- 「横」1 本: s3.2 のケーブル → 13 s1.2。本文が「差動線は第13章の Ethernet と同じ考え」と書く。登録簿の display の down に phy が無いので「横」になる。
- TFT は、ガラスの上の薄膜で作りは違うが、ゲートの電圧でチャネルができる原理は第3章と同じなので「有る」にした（s4.4 の本文も「TFT（第3章のトランジスタ）」）。
- s3.1 と s6.2 の DMA は、第7章 場面4 が装置の「書き込み」だけを見せるので「例が違う」にした（上は読み出し）。
- s6.3 のアンプ → 03 s2.4 は「有る」にしたが、03 s2.4 は「電流は V_G で連続的に変えられるので、アンプとしても使える」の 1 文だけで、負荷を付けて電圧の変化を大きくする所までは見せない。第12〜16章の担当は第12章 場面1 の受信の増幅を同じ理由で「無い」にしている（2026-11-17-p4-12-16.md）。部品 amp を作るなら両方で使える。
- s1.3 のアドレスの式は場面の中で説明し終えているので数えない（27-algorithm.html#s1.1 がこの式を配列の例に挙げるが、データ構造の層で下ではない）。
- s2 の印は 1 つ（s2.5 の演算器）。s2.1〜2.4 は合成の層の中の話で、下の層への依存は s2.2 の掛け算と s2.4 のページフリップ（どちらも無い）だけ。
