## 要点

パスワード管理の 1Password の裏側のサーバーに攻撃者が入った事故で、1Password は、金庫の中身は利用者だけが持つ鍵で暗号化してあり（第20章 場面1）、攻撃者にも読めないと書く。2026-11-25 の発表によれば、攻撃者は社員の会社の GitHub アカウントで裏側のサービスに悪意のコードを送り、一部の利用者の名前・メールアドレス・公開鍵・SRP の値などを落とした。非公開のリポジトリのソースコードも写され、CI/CD の仕組みにも入られた。1Password は、落ちたメールのリンクのトークンと組み合わせる確認のコードを、念のため数字 6 桁から英数字 10 文字に延ばした。

## 中身 <!-- tab: 中身 -->

### 起きたこと

- 2026-11-19、1Password は、社員の会社の GitHub アカウントに攻撃者が入った兆しを調べ始めた。
- 攻撃者が送ったコードは、一部の利用者の記録を落とした。中身は、名前とメールアドレス、アカウントと利用者の識別子、作成と最後のサインインの時刻、公開鍵、SRP の値、招待・プロビジョニング・回復のメールのリンクのトークン、内部の構成に関わる秘密でない値（版やファイルの番号）。人数は書いていない。
- 写されたソースコードは顧客のデータでなく、利用者の秘密も含まないと書く。サービスは止まっていない。
- 影響を受けていないと書くのは、金庫と中の項目、金庫を守る鍵、アカウントの回復の鍵、アプリとブラウザの拡張。アカウントのパスワードと Secret Key は、1Password に保存されていない。

### 原因と仕組み

- 入口は社員の GitHub アカウントで、1Password は盗まれたトークンを無効にした。トークンがどう盗まれたか、侵入がいつ始まったかは書いていない。
- 招待（SCIM Bridge か Hosted Provisioning）と回復の途中にいた利用者は少数で、個別に知らせた。数字 6 桁は 10^6 通り。英数字 10 文字は、大文字と小文字を分けないとしても 36^10 ≈ 3.7×10^15 通りで、約 37 億倍になる。
- 1Password の SRP の解説（2018 年）によれば、登録のとき、端末はアカウントのパスワード・Secret Key・ソルトから PBKDF2 で x を作り、x から検証子を計算してサーバーに送る。サーバーは検証子を保存し、端末へ返さない。
- ログインでは、両端が秘密の数から作った値 A・B だけを見せ合い、x を持つ端末と検証子を持つサーバーが同じ数にたどり着く。解説は、Secret Key があるので、サーバーからデータを得てもパスワードの推測は事実上できないと書く。

### 対策

- 使われた GitHub のアカウントを止め、盗まれたトークンを無効にし、攻撃者が作ったアクセスを消した。漏れたかもしれない内部の資格情報は、すべて替えるか無効にした。
- 確認のコードを英数字 10 文字に延ばした（念のための措置と書く）。GitHub・CI/CD・端末の管理を締め、この種の攻撃を見つける仕組みを足した。
- 漏れたトークンでアカウントが乗っ取られた跡は、内部に見つからなかったと書く。外部の専門家に、封じ込めと修復を確かめさせている。
- 利用者がアカウントで変える物は無い。1Password を名乗る身に覚えのない招待や回復のメール・メッセージ・電話に注意し、パスワードと Secret Key は、自分で開いた公式のアプリかサイトにだけ入れるよう勧める。
