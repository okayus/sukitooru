## 要点

ファイアウォールの通す・止めるの規則（第14章 場面5）を預かる、Check Point の管理サーバーへの侵入の話である。GreyNoise は 2026-10-02〜11-02 に攻撃者 GT13 を観測し、少なくとも 22 の組織の 24 台が乗っ取られていたと突き止めた。攻撃者は中継に使うサーバーを偽の Cookie で乗っ取り、管理サーバーでは内部の認証局で証明書を作り、ファイアウォールのポリシーを外した。最初の侵入の経路は分かっていない。

## 中身 <!-- tab: 中身 -->

### 起きたこと

- 観測は 2026-10-02 13:17:45〜11-02 03:19:46 UTC。攻撃者は管理サーバーに居残れるので、GreyNoise は侵入が今も続くとみる。
- 攻撃者は 99 の IP アドレス（ExpressVPN の出口か、乗っ取った Check Point の機器）を使った。GreyNoise が見たのは、1,400 を超える通信、800 を超えるコマンド、1,200 を超えるファイル（取得・送信・作成）である。
- 被害の組織は、英国・米国・中国・韓国・オーストラリアなど 17 の国と地域の、金融・エネルギー・政府・運輸などの業種にまたがる。地域や業種を絞った様子は無い。
- 被害者 A の中では、65 台のサービスを調べ、ドメインコントローラー・Citrix・Ivanti・Exchange・vCenter の既知の脆弱性を試し、標的に合わせた名前とパスワードでログインを試した。
- 1 台の作業の結果には、`/etc/ld.so.preload` が挙げる `/usr/lib/.libproc.so` を読み込めないという誤りがあった。GreyNoise は、埋め込まれた悪意のプログラムの印かもしれないとみる。
- GreyNoise は攻撃者を既知の集団に結びつけておらず、動機も出どころも判断していない。手作業もあったが、AI のエージェントで脆弱性の探索と攻撃を自動にしていたとみる（推測）。

### 原因

- 管理サーバーに最初にどう入ったかは、分かっていない。攻撃者は、HFS を乗っ取る前から管理サーバーに入っていた。
- 管理サーバーへ命令を送るのに使ったとみられる CVE-2026-16232 は、SmartConsole のログインの処理にある認証の回避で、認証なしにアプリのログインのトークンを得て、全権の管理者として入れる。Check Point は 2026-07-22 に公表し、悪用を把握していると書く。外から悪用するには、管理サーバーの IP にインターネットから届き、Trusted Clients を絞っていない設定が要る。
- 中継の箱の HFS は、2026-07-13 に公表された CVE-2026-61500（3.0.0〜3.2.0 が当たり、3.2.1 で直る）を直していなかった。

### 対策

- GreyNoise は、各国の政府の協力先や CERT と情報を分け、被害者に知らせている。失敗した証明書の作業の結果に被害者の IP アドレスが入っていたので、多くの組織を割り出せた。
- 記事は、攻撃者のドメイン・SSH の HASSH・User-Agent・IP アドレスを、見分ける印（IOC）として挙げる。
- CVE の記録が示す直しは、HFS では 3.2.1 以降。Check Point の記録は、当たる版を R82.10 の Jumbo Hotfix の Take 36 以下などとし、文書 sk185169 を挙げる。

- GreyNoise の記事（2026-11-23。ブログのフィードの日付も同じ）。時刻・数・コマンドとスクリプトの写し・攻撃の基盤の図は、ここから取った。記事は GreyNoise Labs の詳しい版の要約だと書くが、そのリンクは空で、Labs のフィード（最新は 2026-03）にも無かった。
- CVE の記録 [CVE-2026-61500](https://www.cve.org/CVERecord?id=CVE-2026-61500)（VulnCheck、2026-07-13）と [CVE-2026-16232](https://www.cve.org/CVERecord?id=CVE-2026-16232)（Check Point、2026-07-22）。CVE の API の JSON で読み、脆弱性の仕組みと当たる版をここから取った。
- 攻撃者の規則が防いだ欠陥は、前のノート [Linux の IPv4 TCP の解放後の使用 CVE-2026-98432](https://sukitooru.shiraoka.workers.dev/news/2026-10-15-linux-ipv4-tcp-uaf.html) が説明する。
- 手元で確かめたこと: 記事の図の 2 つの Cookie の値を base64 で戻し、時刻を date で読んだ（GNU coreutils 9.4）。応答の物は `sid` に 0.18305… を持ち、偽の物は `username` が admin で、`ts` は 2026-10-02 13:19:33 UTC だった（本文の 13:19:37 と合う）。

- 出典どうしの食い違い: 記事の図の応答の `Date` は 2026-10-02 10:19:02 GMT で、本文の時刻（13:17〜13:19 UTC）より約 3 時間早い。図は、被害者 A の 1 台目から箱へのログインを 11-02 08:52 までとし、本文の観測の終わり（03:19:46）より後になる。どちらも記事に説明は無い。
